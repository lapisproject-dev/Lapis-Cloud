NOTE: The licence statement above follows the MediaPipe model documentation. A reviewer should re-check it against
the model card at the URL above and note the date of that check here.

== Why it is committed and not downloaded at build time

The build must never contact a third-party host: it has to be reproducible, must work without network access in CI
and inside the Docker build, and the running application must never load the model from a CDN either (the participant's
camera frames are processed in the browser, and no third party may learn that a conference takes place). The model is
therefore served from this server under `/assets/mediapipe/selfie_segmenter.tflite`.

== How to replace it

. Download the new model file.
. Update the size and SHA-256 in this document.
. Update the expectations in `VideoBackgroundAssetsTest` (`lapis-server`), which fails as long as the checksum here and
  the file disagree.
. Re-run the manual privacy check from `docs/architecture/video-background-effects.adoc` (no request to a foreign host).

== Pending artefact: the face detector model (V1.9.142)

The camera filters (skin smoothing) need a second model, `blaze_face_short_range.tflite` (MediaPipe BlazeFace short range, Apache-2.0 according to the MediaPipe
model card). It is **not yet in this directory**: fetching it is an external download that was not approved while V1.9.142 was written, and a checksum can only be
written down after the file has been measured -- none is stated here on purpose.

To finish it:

. Download `https://storage.googleapis.com/mediapipe-models/face_detector/blaze_face_short_range/float16/1/blaze_face_short_range.tflite` once (the version-pinned `/1/`
  URL, not `/latest/`) into this directory. Nothing is ever loaded from that host at run time.
. Measure size and SHA-256, check the licence against the model card, and add a second table to this document (source, size, SHA-256, licence, retrieval date).
. In `lapis-client/build.gradle.kts` add `mediapipe/blaze_face_short_range.tflite` to `videoEffectStagedPaths` and its SHA-256 to `videoEffectExpectedSha256`
  (the staging and the webpack copy are both verified), and add a block for it to `VideoBackgroundAssetsTest` (`lapis-server`).
. Run `:lapis-client:jsBrowserProductionWebpack` -- a new asset is not noticed by `check` alone.
. Re-run the manual privacy check from `docs/architecture/video-background-effects.adoc`.

Until then the skin smoothing reports "Pausiert (nicht gestartet)"; light and colour work without the model.
