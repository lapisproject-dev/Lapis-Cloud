= Party accountability report, R1 and R2: architecture (V1.9.225, V1.9.256)
:toc:

NOTE: The `[kuml]` blocks of this document are rendered and validated by the `:docs-render:renderDocs` Gradle task.

See link:../features/partg-report.adoc[the feature description] for what a person sees. This page records how it is built and why.

== Model

[kuml, partg-report-model, svg]
----
classDiagram(name = "PartgReportModel") {
    classOf(name = "partg_report_position") {
        attribute(name = "code", type = "String")
        attribute(name = "section", type = "String")
        attribute(name = "kind", type = "String")
        attribute(name = "org_hint", type = "String")
    }
    classOf(name = "partg_report_sheet") {
        attribute(name = "fiscal_year", type = "Int")
        attribute(name = "unit_key", type = "String")
        attribute(name = "regional_chapter_id", type = "UUID")
        attribute(name = "revision", type = "Long")
    }
    classOf(name = "partg_report_value") {
        attribute(name = "position_code", type = "String")
        attribute(name = "amount_cents", type = "Long")
        attribute(name = "value_source", type = "String")
    }
}
----

* `partg_report_position`: the 42 statutory positions, seeded by `V121__partg_report.sql` with fixed ids; only `org_hint` changes. 35 `LEAF`, 7 `SUM`. `PartgPositions` (lapis-shared)
  is the same catalogue in code; `PartgPositionsSeedTest` pins database and code against each other.
* `partg_report_sheet`: one header per (fiscal year, `unit_key`); carries the revision (optimistic locking) and is the audit entity. `unit_key` is `FEDERAL`, `STATE:<chapter uuid>` or
  `SUB:<chapter uuid>`; `chk_partg_sheet_unit_consistency` keeps it equal to level and chapter, with the UUID text in lower case on H2 and PostgreSQL (`PartgReportMigrationScenarios`, both lanes).
* `partg_report_value`: cents (`0 .. 99999999999999`), one per sheet and `LEAF` position. A missing row is "not entered". That a value may only point to a `LEAF` position is not
  expressible without a trigger; the service enforces it and `PartyReportSaveScenarios` pins it.
* The column is `value_source`, not `source`: `source` collides with `ColumnSet.source` of Exposed.
* The foreign keys onto the natural key `code` need a UNIQUE *constraint* (H2 does not accept a unique index as a target).
* Deviations from the first design, all technical: an `id` column on positions (the audit log needs a UUID entity id), `sheet_id` in the values instead of year and unit per row, and the
  catalogue has 42 rows (35 + 7), not 43.
* The migration is `V121`. V120 is released and not edited. While the wave is unreleased V121 may be corrected in place on the feature branch; after the release every change is a new migration.

== Access and write path

* `requirePartyReportAccess(call)` is the first statement of every RPC method and every route handler (`PartyReportAccessTripwireTest`): role BOARD/ADMIN, then `isPoliticalParty`.
* `PartgReportStore` is the only reader and writer of the three tables (`PartgReportStoreTripwireTest`; the exception is `PartgReportPersonalData`, which lists who changed what).
* One write path, `PartgSheetWriter`, for the RPC `saveSheet` and the import apply route: one transaction; **lock order** regional chapter row, then the sheet of the older year, then the
  sheet of the younger year (`deleteChapter` locks the chapter row first as well, so neither can deadlock the other); the revisions are compared under the lock; the values are applied; the
  audit entries are written last (one per effective value, plus one collective entry for an import with the SHA-256 and the shortened file name); no external effect in the transaction.
* Creating a sheet that a parallel caller creates too: the insert runs under a savepoint, a unique violation is the only SQL error that is caught (PostgreSQL aborts the whole
  transaction after any other), then the winner's row is locked and its revision decides.
* `deleteChapter` refuses with the typed `RegionalChapterHasPartyReportValuesException` as soon as any sheet (even an empty header) of the chapter exists, before any delete runs.
* Writes are limited to 60 per member and minute. Nothing is logged except counts; no amount, no hint, no file name.
* Backup: all three tables are in the generic backup. The restore treats `partg_report_position` as a *seeded set* (fresh unless an `org_hint` exists) and overwrites the 42 rows by id.
* DSGVO: `PartgReportPersonalData` exports "changed by you" without amounts; erasure retains everything (sections 24 and 19a PartG, ten years).

== The XLSX reader (no spreadsheet library)

No Apache POI: a general spreadsheet library is a large attack surface for a file that is only ever read as a fixed template. The reader is small and strict.

[cols="2,3",options="header"]
|===
|Limit |Value
|Upload |2 MB, counted while streaming
|ZIP entries / entry / total / ratio |64 / 8 MB / 20 MB / 100
|Names |printable ASCII, `/` separated; no `..`, no leading `/`, no backslash, no duplicate, no encrypted entry, no symlink
|Macros |any `xl/vbaProject.bin` or a `macroEnabled`/`vbaProject` content type is refused
|XML |StAX, DTD off, no external entities, a DTD or entity event rejects the file; at most 200,000 elements per file
|Cells |only columns A to E, rows up to 500 (content below is an error), text up to 200 characters, at most 5,000 shared strings
|First sheet |found through `workbook.xml` and its relationships; the target must be `xl/worksheets/sheet<1-3 digits>.xml`
|Numbers |`BigDecimal`, rounded to two places when the deviation is below 1e-6 (Excel stores IEEE doubles), else `TOO_MANY_DECIMALS`
|Dates |detected through the number format of the cell style and refused
|Errors |at most 50, then one marker
|===

The ZIP container reader (`OoxmlZipReader`) is **derived from the article import's `ArticleImportZipReader`**. The plan preferred extracting one shared reader; the article reader is fused with
its slug classification and its localized reasons, so the parser core was copied and adapted instead. **The security logic therefore exists twice**; a fix to the central-directory
parsing, the local-header cross check, the overlap check or the bounded inflater has to be applied to both files.

The template writer produces a deterministic file (fixed ZIP time). Organisation and unit names are written as `inlineStr`, never as `<f>`; invalid XML characters are removed.

== The preview store

`PartgImportPreviewStore` keeps the parsed changes between "Prüfen" and "Übernehmen" in memory only: one entry per member, 64 in total (the oldest falls out), 15 minutes on the monotonic clock,
a token of 32 random bytes of which only the SHA-256 is kept and compared in constant time, single use whatever the outcome (a foreign member's guess burns the token). A restart drops
all previews. Apply checks the revisions twice: against the preview and again under the lock.

== Report model (R2)

`PartgReportComputation` (shared, commonMain) is the computing core for client and server. A cell is `Value`, `Partial(cents, missing)` or `NotEntered`, and `NotEntered` is never 0. `PartgPositions.sums`
stays the ONE formula of the seven sums; `inputsOf(sum)` only states which LEAF positions a sum depends on (derived from the catalogue), and `PartgInputsOfParityTest` proves that both agree (raise each leaf
by one, the sum changes exactly when the leaf is in `inputsOf`). `aggregate` adds the entered leaves of several units; a leaf is complete only when every unit entered it. Shares are tenths of a percent by
integer long division, rounded half up (away from zero on a tie), with no Double and no BigDecimal in commonMain. `MAX_UNITS = 201` (federal level plus 100 chapters with two units each) keeps every
sum below 201 x 35 x 99,999,999,999,999 cents inside the Long range, and the percentage division multiplies only the remainder by ten.

`PartgReportStore.enteredSnapshot` reads sheet LEFT JOIN value with ONE statement for all requested years, so the picture is consistent under READ COMMITTED (a loop of `values(sheetId)` would be N+1 and
not consistent). The overview, the checklist (`PartgCompletenessCalculator`) and the export all use it.

== PDF renderer (R2)

`PartgReportPdfRenderer` is its own table builder on PDFBox (A4 landscape, Helvetica, WinAnsi): `LetterPdfBuilder` is portrait. The text clean-up of the Standard-14 fonts lives in `PdfFontText`
(shared with `LetterPdfBuilder`): unencodable characters become `?`, control characters become spaces. Two passes: the content first; then on every page the watermark with `PREPEND` (behind the content,
saved and restored graphics state, `ExtGState` alpha 0.12, `resetContext` so nothing leaks into the content), and the header, legend and "Seite x von y" with `APPEND`. Amount cells are never truncated: each
cell is fitted to its column (8, 7, 6 pt, then smaller); the income matrix uses compact cells (`*` for partial) and splits into two column blocks when the largest amount would not fit 12 columns. A page
break falls only between rows and repeats the header. Limits: pages (`PdfLimitExceeded`), bytes after `save`, and a deadline checked per row. Determinism: no creation date, fixed producer, and an explicit
trailer `/ID` from the SHA-256 of the document (PDFBox otherwise writes a time-dependent ID).

== XLSX export (R2)

`PartgReportXlsxWriter` writes by hand (only `PartgXlsxWriter.escape` is reused; `PartgXlsxWriter` itself is untouched). Every string is `inlineStr`; there is no `<f>` anywhere, no shared strings and no
macro part. The style indices are constants: 2 euro (`numFmtId` 164, with a negative section), 3 percent (165, `0.0%`), 4 quote prefix. A string starting with `= + - @` gets the quote-prefix style;
tab, CR and LF become spaces; invalid XML characters are dropped. Fixed ZIP time and part order, so equal documents give equal bytes.

== Export routes (R2)

`PartgReportExportRoutes.kt` (`GET /api/partg-report/export/pdf|xlsx?year=&scope=`). Order: access gate (the first statement of each handler, pinned by `PartyReportAccessTripwireTest`), rate limit
(10 per member and minute), strict input check (`year`, `scope` = `ALL` or a unit key of at most 48 characters), concurrency permit (`Semaphore(2)`, released in `finally`), ONE read transaction (organisation
name, units, `enteredValues`), assemble and render outside the transaction on `Dispatchers.Default`, audit in its own transaction BEFORE anything is sent (if the audit fails, no file is delivered), response with
a fixed file name, `Cache-Control: no-store` and `nosniff`. The refusal body is the existing `PartgImportRejectionDto`. Only format, year, scope key and counters are logged.

== Migration V136

Only the CHECK of `audit_log_entry.entity_type` is widened by `PARTG_REPORT_EXPORT` (the list is V133's, copied verbatim, plus one). `AuditAction` has no export action, so the entry is a `CREATE` of that
entity type; the format is in the snapshot. `PartgReportSheet` is not reused because it means "one entry per value" and the whole party has no sheet id.

== Client

Route `Routes.PARTY_REPORT`, guarded by `NavVisibility.showsPartyReport(session)` (`SessionInfoDto.politicalParty`, appended at the end with a default). `PartgSheetDraft` holds the
typed-in state without the DOM (blank means not entered, 0 is a value); the live sums use the shared `PartgPositions.sums`, so client and server cannot compute differently. Labels
come from `partgLabel`, one literal `tr(...)` per code. The fourth tab (`PartyReportExport.kt`) loads `reportCompleteness` and the unit list, filters the checklist with the pure `completenessLines`, and starts a download with a temporary anchor (the codebase convention; an error response would be saved as a JSON file, which is why the checklist loads over RPC first). The browser's own question appears when the tab is closed with unsaved values; a change of year, unit or tab asks first.
