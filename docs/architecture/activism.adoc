== Status machine

The single definition is `ActivismTransitions` in `lapis-shared`; the service and the client both use it.

----

    transition(from = running, to = withdrawn, label = "manager")

}

== Locks and concurrency

Every write takes the `activism_action` row `FOR UPDATE` first, then child rows, then (settings setters only) the settings row, and the audit chain row last. No member row is locked. The per-action caps (30 contributions per member, one open report per member) are counted *under the action lock*, so parallel requests cannot slip past them; the Postgres lane runs 40 parallel contribution reports and expects exactly 30. The 5-reports-per-24-hours cap counts across all actions of the reporter while only one action row is locked, so it is a soft cap: parallel reports on different actions can exceed it slightly. The in-process throttle (`ActivismRateLimiter`) runs before the transaction and never inside it. A unique violation (signal pair) is caught under a savepoint, so PostgreSQL does not abort the transaction.

== Single owners (pinned by `ActivismTripwireTest`)

* `ActivismStore` is the only reader and writer of the `activism_*` tables and the two settings columns; `ActivismSignalStore` is the only code that touches `activism_signal` and has no function returning the persons behind a signal. Exceptions: `ActivismPersonalData` and `OrganizationSchemaCatalog`.
* `ActivismAccessPolicy` is the only rights resolver; the service names no account role.
* The package contains no LTR reference and no content filter.

== Open decisions with their defaults

F1 FRIEND/GUEST do not take part (extension point `ACTIVISM_PARTICIPANT`); F2 material is linked, not uploaded; F3 no second approval after changes; F4 the operator does not see who reported; F5 signals are not in the backup; F6 area sums are shown even for one contributing person; F7 "per day" is a rolling 24 hours; F8 BOARD and ADMIN are the operator, TREASURER is not.
