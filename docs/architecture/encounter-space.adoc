= Encounter space ("Begegnungsraum"), server and data protection (V1.9.61, wave B1)
:toc:

== Purpose

An *encounter space* is a standing room with a *pulpit* (one or a few people who speak) and a *congregation* (everybody else, who listens).
The first theme is a church service. It is built on the LiveKit conference stack but is a different thing from the ordinary conference
("Besprechung"): the congregation is *listen-only*, the authority comes from an *office* (not from having created the room), and --
because attending a church service can reveal religious belief, a special category of personal data under Art. 9 GDPR -- the system is
built so that **no lasting trace of who attended remains**.

Wave B1 is the server and the data protection; wave B2 (V1.9.62, <<client>>) is the client. B1 adds no client screen: `IEncounterSpaceService` is the RPC
surface, `V73__encounter_space.sql` the schema, `network.lapis.cloud.server.encounter.*` plus `rpc/EncounterSpaceService.kt` the implementation.

NOTE: This document's `[kuml]` blocks are rendered and validated by the `:docs-render:renderDocs` Gradle task.

== Model

A *space* is permanent configuration. A *session* is one running occurrence: an ordinary `conference_room` row that carries
`encounter_space_id`. The session is "open" while its room row has `ended_at IS NULL`. There is deliberately **no `opened_at` /
`current_room_id` column** on `encounter_space` -- it would need a circular foreign key, and the opening time and the opener already are
`conference_room.created_at` / `created_by_member_id`. "At most one open session per space" is enforced by the row lock on the space (see
<<lock-order>>), not by a constraint.

[source,kuml,name="encounter-space-model"]
----
classDiagram(name = "Encounter space -- ERM excerpt") {

        target { multiplicity(spec = "0..*"); role = "offices" }

----

* `encounter_space` -- title, description, `theme_key` (`CHURCH`), `mode` (`SERVICE`), `guest_policy` (`MEMBERS_ONLY` /
  `MEMBERS_AND_GUESTS`), `max_participants` (`NULL` = the instance maximum; the service clamps it to `ConferenceConfig.maxParticipants`),
  `closed_notice` (free text such as "Gottesdienst beginnt um 10:15 Uhr" shown while closed -- no time field on purpose), `archived_at`.
* `encounter_space_role` -- the *office* configuration: who is `PULPIT` or `STEWARD` ("Ordner") of a space. Composite primary key
  `(space_id, member_id)`: one office per member per space. Never the congregation.
* `encounter_consent_acknowledgment` -- the accountability proof of a *non-member's* explicit consent (<<consent>>). Composite key
  `(member_id, consent_version)`, **no room or space reference and no timestamp -- only a date**, so it cannot be read as an attendance record.
* `conference_room.encounter_space_id` -- `NULL` for every ordinary room.

=== States

[source,kuml,name="encounter-space-session-states"]
----
stateDiagram(name = "Encounter space and its sessions") {
    val start = initialState()
    val closed = state(name = "CLOSED (space active)")
    val open = state(name = "OPEN (one session running)")
    val archived = state(name = "ARCHIVED")

    transition(source = start, target = closed) { trigger = "createSpace (BOARD/ADMIN)" }
    transition(source = closed, target = open) { trigger = "openSpace (office holder, BOARD/ADMIN)" }
    transition(source = open, target = closed) { trigger = "closeSpace / poller: EMPTY or MAX_DURATION" }
    transition(source = closed, target = archived) { trigger = "archiveSpace (BOARD/ADMIN, only while closed)" }
}
----

A session is closed for one of three reasons, all audited with the same snapshot shape `{"state":"CLOSED","reason":...}`: `MANUAL`
(`closeSpace`), `EMPTY` (the LiveKit room is gone) or `MAX_DURATION` (older than 12 hours). Closing deletes the LiveKit room and **deletes
every presence row** (<<privacy>>).

== Offices and access

The office is *re-derived from the database on every call*; nothing is cached and the participation row is never an authorization source.
An office only counts while the holder is `ACTIVE`: a withdrawn or rejected member loses it the moment the status changes, with no cleanup job.

[cols="2,1,1,1,1,1,1", options="header"]
|===
| Operation | BOARD/ADMIN | PULPIT | STEWARD | other ACTIVE | GUEST/FRIEND | other status
| list / get / entry info | yes | yes | yes | yes | only `MEMBERS_AND_GUESTS` | no
| create / update / archive / list+set roles | yes | no | no | no | no | no
| open / close a session | yes | yes | yes | no | no | no
| enter | yes (listen only) | yes (may speak) | yes (may speak) | yes (listen only) | yes, after consent (listen only) | no
| leave | yes | yes | yes | yes | yes | yes
| list who is present | only if present | only if present | only if present | only if present | only if present | no
| remove / silence | anybody | congregation only | congregation only | no | no | no
|===

* An archived space is visible to BOARD/ADMIN only (a `NotFoundException` for everybody else); a guest policy miss is a `ForbiddenException`.
* **BOARD/ADMIN without an office listen only** (`canPublish = false`) but may moderate. Speaking requires an office.
* A PULPIT or STEWARD holder may remove or silence only members of the congregation, never another office holder and never BOARD/ADMIN; only
  BOARD/ADMIN may. Nobody moderates themselves.
* `setSpaceRoles` is replace-all, at most 20 assignments, no duplicate member, every member `ACTIVE` at the time of the assignment.

=== The token: two shapes, one service

`LiveKitAccessToken.mintParticipantToken` takes `canPublish` and `canPublishData` as *required* parameters (no default), so the compiler forces
every call site to decide. An ordinary conference passes `true, true` (byte-for-byte the grant map of before). The *congregation* token has
`canPublish = false`, `canSubscribe = true`; a person a steward silenced additionally has `canPublishData = false`. The token is never
`hidden`, never `recorder`, never carries an admin grant. Token lifetime: non-members `guestTokenTtlMinutes` (15), members `tokenTtlMinutes`.

=== The ordinary conference RPC surface is fenced off

The congregation's listen-only token is enforced *by the server when it mints the token*. `ConferenceService.joinRoom` and
`ConferenceBreakoutService.rejoinMainRoomToken` mint tokens with `canPublish = true` for any `ACTIVE` member. If they accepted the id of an
encounter session, any congregation member could ask for a publishing token for the same LiveKit room and speak from the pulpit. That
would make "listen only" worthless, so `EncounterRoomGuard.requireNotEncounterRoom` is the *first* statement of every room-id method of the
six conference services (and of `requireRoomEntryAuthorization`, which the shared entry gate uses).

[cols="2,3", options="header"]
|===
| Service | In an encounter session
| `ConferenceService` | `getRoom`, `joinRoom`, `leaveRoom`, `endRoom`, `listParticipants`, `removeParticipant`, `renameRoom`, `getGuestJoinInfo`, `setRoomGuestAccess`, `setRoomMeeting`, `getRoomVotingState`: all refused. `listActiveRooms` and the lazy reconciliation skip encounter rooms (they would close a session by `left_at` instead of deleting the rows).
| `ConferenceBreakoutService` | every room-id method refused, including `rejoinMainRoomToken` and (defence in depth) `requestBreakoutJoinToken`. `returnToMainRoom` only closes the caller's own assignment row.
| `ConferenceRecordingService` | `startRecording`, `getActiveRecording` refused: a recording would be a lasting record of who was in a church service.
| `ConferenceNotesService`, `ConferenceWhiteboardService` | every method refused (attributed, persistent content).
| `ConferenceStreamingService` | allowed, but `startStream` only with layout `SINGLE_PARTICIPANT` on an `ACTIVE` `PULPIT` holder: the congregation never reaches an external platform. `getActiveStream` stays visible to everybody present ("everybody in the room may know a stream runs").
|===

`ConferenceModeratorAuthority` replaces the six private copies of `requireModeratorOrPrivileged`: ordinary room = creator or BOARD/ADMIN
(unchanged), encounter session = `ACTIVE` office holder or BOARD/ADMIN. **The one who pressed "open" has no special right**: an office can be
withdrawn while a session runs and must take effect at once. `EncounterRoomGuardTripwireTest` fails the build if a room-id method stops
referring to the guard.

[#privacy]
== Data protection by construction (Art. 9 GDPR)

* **Presence is transient.** `enterSpace` inserts one `conference_participation` row (at most one per session and person, a reconnect reuses
  it). `leaveSpace` *deletes* it (no `left_at` is ever kept), `closeSpace` deletes all rows of the session, and `EncounterSpacePoller`
  deletes what a crashed client left behind. `conference_guest_consent_acknowledgment` is *never written* for an encounter session; if such a
  row existed it is deleted with the session.
* **`listPresent`** answers only a person who is present themselves, sorted by name (the order must not reveal who arrived when), without
  times and without home servers. BOARD/ADMIN who are not in the room see nothing: no surveillance from outside. `EncounterSpaceDto.presentCount`
  is only a number.
* **The audit log** receives configuration changes (`create`, `update`, `archive`, `setSpaceRoles`, actor = BOARD/ADMIN) and open/close
  (actor = the office holder, or `null` for the poller's automatic close). **Never** entering, leaving, presence, removing or silencing:
  the log is hash-chained and cannot be erased, so an entry "member X was in the church service" would be a permanent trace.
  `setSpaceRoles` records the office holders' member ids (an office is an act of the organization and the assignment of rights must be
  traceable); the alternative -- only counts -- is an open question.
* **Moderation state** (who was removed, who was silenced) lives only in memory (`EncounterModerationState`, bounded to 64 sessions and 200
  entries per list; a full list *refuses* instead of evicting a block) and is dropped when the session ends. A database block list would be a
  lasting record about a person. Consequence: it is lost on a server restart.
* **Logs** in the encounter code never name a member id, an identity, a display name or a room id above DEBUG. Stream keys are untouched
  (`SecretBox`). `EncounterPrivacyTripwireTest` and `EncounterPrivacyWatchTest` pin all of this.
* **Export and erasure** (`EncounterSpacePersonalData`): the export lists the subject's own spaces, offices and consent proofs. Erasure
  *deletes* the office rows and *retains, with the reason*, the spaces the member created (organization configuration) and the consent proof
  (Art. 5(2)/7(1) accountability).

[#consent]
=== The consent of a non-member

A GUEST or FRIEND must explicitly consent (Art. 9(2)(a)) before entering a space with `MEMBERS_AND_GUESTS`. `getEntryInfo` returns
`consentRequired` and the text; `enterSpace` takes the version and hash *unmodified* (`EncounterConsentDisclaimer.matches`, constant time). The
proof is one row `(member, version)` with the hash and a *date*, written inside a savepoint (`isUniqueViolation()` is the only exception
swallowed -- on PostgreSQL a failed statement would otherwise poison the transaction). Consent given once covers every space for that version.
For an `ACTIVE` member a submitted consent is ignored and nothing is stored. **The text is a draft** and needs legal review.

== Session lifecycle and the poller

`openSpace` is idempotent (an open session is returned unchanged): transaction 1 authorizes, the LiveKit room is created *outside* any
transaction (`empty_timeout` 1800 s for a room nobody has joined yet, plus `departure_timeout` 1800 s for a room whose last participant left, so a break or a dropped pulpit connection does not tear the session down), transaction 2 re-verifies under the locks and inserts the room
row. A call that loses the race deletes its freshly created LiveKit room again. `closeSpace` deletes the LiveKit room first (a failure is only
logged -- data protection beats availability, the poller retries), then ends the session and deletes the rows under the locks.

`EncounterSpacePoller` runs at start and every 60 s: (a) deletes presence rows of ended sessions -- always, even if LiveKit is down;
(b) per open session deletes presence rows of people no longer connected (older than 120 s *and* absent in two consecutive sweeps, because
`livekit-client` reconnects with its still-valid token without calling `enterSpace` again, so one sweep inside a short network gap must not
cost a person their row), disconnects blocked people who reconnected with a still-valid token; (c) closes a session that is older than 12
hours (`MAX_DURATION`, done *before* any LiveKit call, so an outage cannot keep it open past its limit) or whose LiveKit room is gone
(`EMPTY`); (d) retries the LiveKit deletion of sessions that ended in the last 24 hours. If LiveKit is unreachable, (b), the room-gone part
of (c) and (d) are skipped with a warning that carries no ids. A client that is told its connection was re-established need not call
`enterSpace` again; if it does, that is harmless.

[#lock-order]
== Lock order and transactions

Every writer takes the locks in this order, without exception: (1) `encounter_space FOR UPDATE`, (2) `conference_room FOR UPDATE`, (3) the
caller's status is *read* without a lock, (4) inserts and deletes, (5) `AuditLogRecorder.record` *last*. Never `FOR UPDATE` on `member`
(see `docs/architecture/row-locks.adoc`). LiveKit and HTTP calls are never inside `transaction {}`. The ceilings are enforced inside the
locked transaction:

* The congregation stops `2` places short of the maximum (`ENCOUNTER_OFFICER_RESERVED_SLOTS`), so a full congregation can never lock the pulpit
  out; office holders and BOARD/ADMIN use the reserve; the hard maximum (LiveKit `max_participants`, at most 25) holds for everybody. A
  reconnecting person already present is never turned away.
* At most `maxNonMemberParticipants` (20) non-members.

== Assumptions about LiveKit

* A token with `canPublish = false` is believed to be *enforced by LiveKit* (the grant is part of the signed token). This is **not verified
  against a live instance** in this wave; `docs/architecture/encounter-space-staging-test.adoc` is the test script for it. `hidden` is not used.
* `removeParticipant` disconnects but does not invalidate the token: a removed person who still holds a valid token can reconnect to LiveKit
  directly. The server blocks re-entry (`enterSpace`) and the poller disconnects blocked identities again within its period (60 s). A *silenced*
  person's old token still carries the data channel; the poller compares the live `permission.can_publish_data` of every silenced identity and
  disconnects it again within its period (60 s), so the bypass window is bounded by the sweep, not by the token lifetime.
* A withdrawn office: `setSpaceRoles` disconnects (best effort, after the commit) every ex-holder who is present in the running session, and
  a re-entry via `enterSpace` gets a listen-only token. Even after a successful disconnect, the old token (`canPublish = true`) allows a
  direct reconnect to LiveKit; the poller therefore disconnects, every sweep (60 s), any live participant that holds publish rights
  (`permission.can_publish` or published tracks) without being a current ACTIVE office holder. Only re-entry via `enterSpace` is listen-only.
  The moderation checks of the server are unaffected.
* `auto_create` (LiveKit default `true`) would revive a deleted room when somebody connects with an old token; the server checks that the
  session is open when a token is requested, and the poller closes the session record.

[[client]]
== Client (wave B2, V1.9.62)

The client lives in `lapis-client/.../client/encounter/` (every file starts with `Encounter`, so the source tripwires can find it). Nothing in
this section changes the server except one route (<<client-mobile>>) and one enum value.

=== Routes and navigation

[cols="2,3", options="header"]
|===
| Route | What
| `#/begegnung` (`Routes.ENCOUNTER`) | the list of rooms, `EncounterSpaceScreen`; BOARD/ADMIN additionally create, edit, assign offices and archive
| `#/begegnung/:spaceId` (`Routes.ENCOUNTER_SPACE`) | one room, `renderEncounterServiceView`; registered *before* the list route like the conference
|===

Both sit behind `requireAuth`: who may see or enter a room is decided by `IEncounterSpaceService`, never by the route. The sidebar gets a third
flat entry "Begegnungsräume" (`NavVisibility.showsEncounterSpaces`: ACTIVE, GUEST and FRIEND, the `CONFERENCE_ELIGIBLE` set) -- a guest has no
group to find it in.

=== The three phases of a room

[source,kuml,name="encounter-client-phases"]
----
stateDiagram(name = "Encounter room view (client)") {
    val start = initialState()
    val closed = state(name = "Closed")
    val entry = state(name = "Entry")
    val inside = state(name = "Inside")

    transition(source = start, target = closed) { trigger = "getEntryInfo: doors closed" }
    transition(source = start, target = entry) { trigger = "getEntryInfo: doors open" }
    transition(source = closed, target = entry) { trigger = "doors opened (poll every 30 s, or openSpace)" }
    transition(source = entry, target = inside) { trigger = "click Eintreten: enterSpace + connect" }
    transition(source = inside, target = closed) { trigger = "doors closed / session ended" }
    transition(source = inside, target = entry) { trigger = "Verlassen, connection lost, re-entry refused" }
}
----

* *Closed*: the notice of the room (untrusted text) or a plain sentence; a moderator gets "Türen öffnen".
* *Entry*: `EncounterEntryPanel`, deliberately *not* a modal. Three plain sentences, the Art. 9 remark ("Dieser Hinweis ist keine Rechtsberatung."), for a
  non-member the server's consent text (headline and key points as untrusted text, the full text behind a disclosure, a required tick box). The version and the
  hash go to `enterSpace` unmodified. There is no link to any streaming platform: whether the pulpit is transmitted is the operator's decision.
* *Inside*: `EncounterRoom`. A disconnect with the reason `DUPLICATE_IDENTITY` (the same account entered on another device) is decided first: the room view is replaced by the
  "connected on another device" card with "Hier fortsetzen" / "Zur Übersicht"; no `getSpace`, no re-entry, no `leaveSpace` (that would delete the presence row and the poller would then
  disconnect the other device). Any other disconnect: the state is read: closed means "Der Gottesdienst ist beendet."; open means one automatic re-entry
  (at most 3 per 5 minutes), then the entry panel again; a refusal on re-entry means "Sie wurden aus diesem Raum entfernt.".

The room view's teardown is the destroy hook of the screen root, registered *before* the root is added (see `addWithLifecycle`): leaving the route stops every timer and
listener, disconnects the session and calls `leaveSpace`. A closing page does the same best effort on `pagehide` (a plain RPC can be cancelled by the browser then; the
server's presence poller removes a stale row).

=== Listen-only, three layers

. The server mints the token with `canPublish = false` for everybody without an office (B1).
. *The type*: `EncounterMediaSession.kt` hands a congregation member an `EncounterListenerSession`, an interface *without any media method*. Only an entry with
  `canPublish = true` yields an `EncounterSpeakerSession` (with `setCamera`/`setMicrophone`). The code that could switch a camera on does not compile for a listener.
. *The runtime flag*: `LiveKitRoomSession(publishEnabled = entry.canPublish)`. With `false`, `setCamera`/`setMicrophone`/`setScreenShare` return at once without touching the SDK, and
  device listing, switching and enumeration are empty or refused (some browsers answer an enumeration with a permission heuristic). The conference keeps the default `true`.

A pulpit person's camera is switched on in the same click chain that entered (so Safari's gesture rule is met); the microphone stays off, with a standing status band "Ihr Mikrofon ist aus." (`role="status"`).
A steward starts with both off.

=== Scene, pews, reactions

* *Two layers* (design team, Duarte): the scene `lapis-encounter-scene-front`/`-rows` are decorative CSS masks of the floor plans under `/assets/encounter-themes/<theme>/` (since V1.9.67, see <<stage-1>>; set inline by the layout, colour and visibility from `theme.css`; own drawings, vector only, `aria-hidden`);
  the stage on top holds opaque surfaces (pulpit, stewards' strip, seats, name labels), so text never sits on the motif. Contrast pairs are documented in `theme.css`
  (`--lapis-encounter-*`, light and dark). "Szene aus" removes the layer; forced-colours and `prefers-contrast: more` hide it automatically.
* *Pews* (`EncounterSeating`): 2 blocks of 3 seats per row, an aisle between, filled alternately left/right from the front; the plan grows by one row of six when full and never
  shrinks. A seat never moves; a leaving person leaves an empty seat. The plan is *per device* (nothing is synchronised, nothing could record who sat where); the people already
  present sit down in name order so the order of arrival is not readable. Only people `listPresent` names get a seat -- a LiveKit participant that is not listed (an egress bot, a stranger) never does.
  A seat is a `listitem` of the `list` "Gemeinde" with an accessible name, no button, no tab stop.
* *Reactions* (data-channel topic `lapis-encounter-reaction`, payload `{"r":"<NAME>"}` only, at most 32 bytes (the longest, `HAND_LOWERED`, is 20)): `HAND` is a *state* (renewed every 30 s by its owner, lapses after 90 s,
  `HAND_LOWERED` ends it), `AMEN` an *event* (a symbol at the seat for 3 s, announced as the fixed sentence "Amen aus der Gemeinde" at most every 10 s, never a number). Limits: sender
  amen 5 s / hand 2 s, receiver 2 per second and sender, the sender table bounded to 64. **Trust boundary**: the receiver reads only the key `r`; the sender is the SDK-verified identity of the packet,
  never a payload field; oversize and malformed payloads are dropped unread; only people who sit can react.
* *Raised hands* are listed (in the order they went up) only for office holders and BOARD/ADMIN; the congregation sees seats, not a queue.
* *Chat* reuses the conference's topic `lapis-chat`: in-memory only, at most 200 lines of 500 characters, plain text (no markup, no links, the KVision i18n marker neutralised), and *no time*
  (the wire field is sent as `0`). A silenced person (`canPublishData = false`) can read but not write.

=== Moderation and transmission

* The menu "Stummschalten"/"Entfernen" (`encounterCanActOn`): never for oneself, never for the congregation viewer; an office holder acts against the congregation only (the server refuses another office
  holder and BOARD/ADMIN -- the client cannot see a congregation member's global role, so an office holder may see the menu for a BOARD member and the server then refuses; the client says so in one fixed sentence).
  "Entfernen" asks first. The guest marker "Gast" is shown only to people who moderate.
* The transmission tab (`EncounterStreamPanel`, moderators only) starts and stops the transmission of the *pulpit*: the layout is fixed to `SINGLE_PARTICIPANT` ("Nur Kanzel", no choice), the picture is the pulpit person's
  (a choice only with more than one), the latency is the conference's default (`STANDARD`). It creates and activates no destination, in particular no YouTube destination; administrators get a link to the
  destination screen. Pause and resume are not part of B2.
* The badge "Live (nur Kanzel)" is shown to *everybody present* while a stream runs: the server's transparency read (`getActiveStream`) is allowed for all present people. It is polled every 30 s while the
  page is visible; a conflict answer (streaming not enabled) stops the polling.

=== Polling and the rate budget

The server's `list` budget (60 per minute and member) is shared by `listSpaces`, `getSpace`, `getEntryInfo` and `listPresent`. The client therefore refreshes `listPresent` at most every 5 s on a roster event
(merged: `EncounterRefreshPlanner`), every 20 s by timer, and only while the page is visible; a closed room is asked every 30 s; re-entry after a disconnect is limited to 3 per 5 minutes (the `enter` budget is 30 per minute).

=== Accessibility

Controls are real buttons with names; the hand button carries `aria-pressed` (fixed label); the pulpit is a `group` named "Kanzel: <name>" and receives the focus after entering (`tabindex=-1`); two polite live
regions (amen bundling for everybody, "<name> hebt die Hand" for office holders only); no single-letter shortcuts; the side panel is closed by default, Escape closes it, below 768 px it is a full-screen sheet
(`role="dialog"`, `aria-modal`, focus trap, focus returns to the opener); amen fades in and out in 200 ms, switched off under `prefers-reduced-motion`; on a narrow screen the controls are a fixed 56 px bar with icon and label.

=== Browser storage

The only storage of the encounter client is the key `lapis.encounter.sceneOff` (value `1`): no room, no person, no time (`EncounterSceneToggle.kt`). Reading or writing it is wrapped in `try`/`catch`; a blocked
storage means "scene on". `ClientEncounterPrivacyTripwireTest` pins this together with the other privacy rules (no `innerHTML`, no console, no exception text, devices only in the two allowed files, no telemetry).

[[client-mobile]]
=== Mobile bridge

`GET /api/mobile/v1/encounter/spaces/{spaceId}/webview-session` (same header-only bridge as the conference route, same kill switch `LAPIS_MOBILE_WEBVIEW_BRIDGE_ENABLED`) lands on `/app#/begegnung/<id>`; the section key
`encounter` lands on the list. The id is matched against the allowlist charset (`^[A-Za-z0-9_-]{1,64}$`) and never reflected; there is no existence or visibility check in the route (the page's own RPC decides; an unknown id ends in the client's
"not found" state). Nothing is logged about the id.

=== Known limitations of B2

* B1's staging script was not run when B2 was built: that LiveKit really enforces `canPublish = false`, and the exact client-side symptom, are *assumptions* (the client prevents the attempt, the token refuses it).
* Safari: audio output echo is possible without headphones; the autoplay band "Ton einschalten" is the fallback for a listener who has never touched the page.
* The room is sized for a congregation of about 20; the pews grow by rows, nothing is virtualised.
* `listPresent` sends `isGuest` to every present person; the page shows it only to moderators. Data minimisation would need a server change (not part of B2).
* The LIVE badge is visible to everybody present (a transparency right of the server), not only to office holders.
* Translations (7 languages) were written for this wave and not reviewed by native speakers.
* No test on a real device; the Karma tests run in headless Chrome.
* Not included: pause/resume of the transmission, a help page, activating a destination, a request-to-speak flow, subtitles, further scenes.

[[stage-1]]
== Stage 1 (V1.9.67): room profiles, configurable reactions, stage mode, floor-plan scenes

A room now has a *profile* (`encounter_space.profile`, V76) and a *reaction set* (`encounter_space.reaction_set`). Both describe the *room*, never a person: no new
table, no new column with personal data, no log of reactions, so the Art. 9 position of the room is unchanged.

=== Profiles and vocabulary

[cols="2,3,3"]
|===
| | `CHURCH_SERVICE` (default, every existing room) | `ASSEMBLY`

| Who speaks | Kanzel (pulpit) | Podium
| Who moderates | Ordner im Gottesdienst | Moderation
| Who listens | Gemeinde | Teilnehmende
| Default reactions | hand, amen | hand, applause
| Scene | chancel, pews | podium, chairs
| Consent text | `EncounterConsentDisclaimer` (`2026-10-06.v1`) | `EncounterAssemblyConsentDisclaimer` (`2026-10-07.assembly.v1`)
|===

All profile words live in one client file (`EncounterVocabulary.kt`, `EncounterTerms`); `ClientEncounterVocabularyTripwireTest` fails the build if another file of
`client/encounter/` writes one of them as a literal or branches on the profile. `theme_key` stays frozen at `CHURCH` so a cached old client still decodes `EncounterTheme`;
the profile is the truth. Existing rooms get `CHURCH_SERVICE` and `HAND,AMEN` from the migration: the behaviour of a running church room does not change.

=== Reaction set

`HAND`, `AMEN`, `APPLAUSE`, `HEART`. There is deliberately no thumbs-up: in an assembly it reads as a vote. `HAND` is always on (a person must always be able to ask for the floor);
`HAND_LOWERED` is the wire counterpart of `HAND` and is never selectable. The server stores the canonical list (`EncounterReactionOption.normalize`: deduplicated, fixed order, `HAND` first)
as a CSV and rejects a list of more than 8 entries (DoS guard). The order of the buttons is fixed. The set is enforced *on the client only*: the server never reads a reaction (data channel,
no server path), so the client builds a button per allowed option and drops a received reaction the room does not allow (`admitReaction`; silent, no log, no counter). A manipulated client can
still send anything; the 32-byte limit, the per-sender receive limit and "only people who sit can react" stay in force. The three event reactions share one 5 s send budget; the hand has its own 2 s budget and
is never blocked by an event. A seat has one event slot (a newer event replaces the older), announced as one fixed sentence at most every 10 s, never as a count.

=== Changing the profile

`createSpace`: `profile = null` means `CHURCH_SERVICE`, `reactions = null` means the defaults of the profile. `updateSpace`: `null` means *unchanged* -- an old cached admin client sends neither field
and must not silently turn an assembly into a church service. A real change of profile or reactions while a session is open is a `ConflictException` (same pattern as the guest policy): the
vocabulary and the reaction set cannot change under people who are present. Unchanged values while open are accepted; title, description, notice and maximum stay editable. Only BOARD/ADMIN, as before.
The audit snapshot (`configSnapshot`) gets `profile` and `reactions` (room values only; the only member id in an audit entry is still the actor's).

=== Consent per profile

The consent a guest gives is bound to a text (`encounterConsentFor(profile)`). A guest who consented for a church service must consent again for an assembly: the purpose is another (Art. 9: a political
opinion or worldview instead of a religious belief). `getEntryInfo`, `enterSpace` (version and hash must match the room's own text, constant-time compare), the stored proof and `hasCurrentConsent` all use the room's text.
The church text and its hash are unchanged, so existing consents stay valid. *The assembly text is a draft and MUST be reviewed by a lawyer.*

=== Stage mode

* The room fills at least the height under the header (`--lapis-header-h`, a token) minus the bar; `100vh` first, `100dvh` second (older Safari has no `dvh`). The pulpit/podium keeps 16:9 and takes at most
  62 % of that height; the old 720 px cap is gone (`ClientEncounterVocabularyTripwireTest` pins that). The benches sit below. Since V1.9.68 (R59, one scroll surface) the height is a minimum, not
  a fixed size: the room grows with its benches and the page scrolls; there is no inner scrolling area for the benches any more. In full screen the room itself is the scroll container
  (ledger entry E0 of `ScrollSurfaceTripwireTest`, see `ui-ux-guideline.adoc` R59).
* The side panel: from 1200 px a 340 px column (closable), from 768 to 1199 px an *overlay* over the right edge (closed by default, Escape closes it, focus returns to the opener), below 768 px the full-screen sheet.
  The toggle carries `aria-expanded` and `aria-controls`; the state lives in memory only.
* Full screen (`EncounterFullscreen`): the Fullscreen API on the room element; without it (or when `requestFullscreen()` is rejected) the room gets `is-pseudo-fullscreen` (`position: fixed; inset: 0`) and Escape leaves it.
  Listeners are removed when the person leaves. Nothing is stored.
* The bar (`EncounterControlBar`) has groups: reactions | devices (office holders) | panel | view (scene, full screen) | moderation. Targets are at least 44 px; below 768 px only the symbols are visible (the text stays as the accessible name).
  The "Verlassen" button stays in the page header: in full screen the header is not visible, Escape leaves the full screen first.

=== Floor-plan scenes

`church/{front,row}.svg` and `hall/{front,row}.svg` (drawn for this project, see `PROVENANCE.adoc`), loaded as CSS masks: the front once at the top, the row (352 x 56 units) tiled behind the seats (`--lapis-enc-row-w` x `--lapis-enc-row-h`
equal one row of seats; a DOM test checks that against the seat grid). Colour only from `--lapis-encounter-scene-ink`/`-tint` (light and dark); hidden in `forced-colors` and `prefers-contrast: more`; "Szene aus" removes both layers.
The old front view `church.svg` was removed.

=== Known limitations of stage 1

* Not tested on a real device, in Safari or in the mobile WebView (`Lapis-Cloud-Mobile`), where the Fullscreen API is often missing: the CSS fallback exists but was not seen there.
* The translations (en, fr, nl, it, es, pl, ru) are agent translations, not reviewed by native speakers.
* Profile and reactions are enforced on the client only (see above).
* The order of the reaction buttons is fixed; a custom order is not part of stage 1.
* There is no organization-wide default profile (it would need a column and a settings page in `organization_settings` and a further permission surface; two to five rooms per organization do not justify it yet).
* The assembly consent text has not been reviewed by a lawyer.
* Stages 2 and 3 of the encounter-room plan (not part of this wave) are not included.
* Wire compatibility with a cached old tab is proven by a test (`EncounterWireCompatTest`: Kilua's JSON ignores unknown keys), not by a live old client.
* The header height token `--lapis-header-h` is a fixed estimate (navigation plus page header); a taller header shortens the stage, `min-height: 480px` keeps it usable.
* The side navigation still shows a church symbol for "Begegnungsräume" in every organization (open question, not changed in this wave).
