= Democratic elections, server integrity (V1.9.23)
:toc:

== Purpose

A motion can be decided in four ways: the committee quorum (`resolveMotion`, `recordResolution`), a meritocratic vote
(`openVote`/`closeVote`), a systemic consensus (`evaluate`) and an election (`tally`). Until V1.9.22 nothing on the server stopped two
of them from deciding the same motion, and several election methods read the election row without any lock. V1.9.23 makes the
four paths mutually exclusive and every election transition serialized. It adds one additive migration, `V64__election_integrity.sql`.

NOTE: This document's `[kuml]` blocks are rendered and validated by the `:docs-render:renderDocs` Gradle task.

== Lock order

Every decision-relevant transaction takes its locks in the same order, so no two of them can wait for each other in a cycle.

[cols="1,3,3", options="header"]
|===
| Step | Lock | Taken by
| 1 | `motion` row, `FOR UPDATE` | `openElection`, `tally`, `abortElection`, `openVote`, `closeVote`, `abortVote`, `resolveMotion`, `withdrawMotion`, `recordResolution` (per agenda item, ascending id), `openSystemicConsensus`, `evaluate`
| 2 | `election`, `vote` or `systemic_consensus` row, `FOR UPDATE` | all election methods, `closeVote`, `abortVote`, `evaluate`
| 3 | `conference_room` / stream rows | `openVoting` for a secret election (after the electorate snapshot)
| 4 | `member` row (`requireActiveMembership(forUpdate = true)`) | `appointElectionBoard`, the winner seating in `tally`
| 5 | audit log chain | always the last write (`AuditLogRecorder`)
|===

A method that starts from a child id (an election id, a vote id) first reads the child's `motion_id` without a lock -- the column never
changes -- then locks the motion, then re-reads the child row `FOR UPDATE` and does every check on the re-read row. A method that
never touches the motion (`castElectionBallot`, `approveTally`, `closeVoting`, `openVoting`, `releaseCandidateList`, candidacies) locks
only the election row; it cannot be part of a cycle because it never waits for the motion. `forUpdate()` is only used on single-table
selects (H2 rejects it on joins). The helpers are in `MotionDecisionLock.kt`.

== Mutual exclusion of the decision paths

[cols="3,1,1,1,1", options="header"]
|===
| While ... exists | election | vote | systemic consensus | quorum resolution
| an election (`election.active_motion_id`): any non-`ABORTED` one blocks `openElection` (unique index); only a running one (`PREPARATION` to `CLOSED`, not `TALLIED`) blocks the other paths | `openElection` refused | `openVote`, `closeVote` refused while running | `openSystemicConsensus`, `evaluate` refused while running | `resolveMotion`, `withdrawMotion`, `recordResolution` (agenda item) refused while running
| a vote that is `OPEN` or `CLOSED` | `openElection` refused | -- | `openSystemicConsensus` refused | allowed (see follow-ups)
| a systemic consensus that is not `ABORTED` | `openElection` refused | `openVote` refused | -- | allowed (see follow-ups)
|===

Also while an election runs: `withdrawMotion` is refused (the election would become untallable -- abort it first), and `tally`,
`closeVote` and a binding `evaluate` additionally require the *locked* motion row to still be `SCHEDULED`.

`resolution_id` is deliberately not part of the "undecided" test: a motion that was `POSTPONED` and scheduled again still carries its
earlier resolution, and must be decidable again. The status of the locked row is what counts.

== Election transitions

Every arrow is one transaction that holds the election row lock; `tally` and `abortElection` hold the motion lock first.

[source,kuml,name="elections-integrity-election"]
----
stateDiagram(name = "Election, locked transitions") {
    val start = initialState()
    val preparation = state(name = "PREPARATION")
    val released = state(name = "CANDIDATE_LIST_RELEASED")
    val open = state(name = "OPEN")
    val closed = state(name = "CLOSED")
    val tallied = state(name = "TALLIED")
    val aborted = state(name = "ABORTED")

    transition(source = start, target = preparation) {
        trigger = "openElection (motion lock)"
        guard = "[motion SCHEDULED, no other decision path]"
    }
    transition(source = preparation, target = released) { trigger = "releaseCandidateList (election lock)" }
    transition(source = preparation, target = open) { trigger = "openVoting (election lock, one snapshot)" }
    transition(source = released, target = open) { trigger = "openVoting (election lock, one snapshot)" }
    transition(source = open, target = closed) { trigger = "closeVoting (election lock)" }
    transition(source = closed, target = tallied) {
        trigger = "tally (motion, then election lock)"
        guard = "[approvals >= threshold, motion SCHEDULED]"
    }
    transition(source = preparation, target = aborted) { trigger = "abortElection (motion, then election lock)" }
    transition(source = released, target = aborted) { trigger = "abortElection" }
    transition(source = open, target = aborted) { trigger = "abortElection" }
    transition(source = closed, target = aborted) { trigger = "abortElection" }
}
----

== Motion transitions around an election

[source,kuml,name="elections-integrity-motion"]
----
stateDiagram(name = "Motion, decision paths") {
    val scheduled = state(name = "SCHEDULED")
    val resolved = state(name = "RESOLVED")
    val rejected = state(name = "REJECTED")
    val postponed = state(name = "POSTPONED")
    val withdrawn = state(name = "WITHDRAWN")

    transition(source = scheduled, target = resolved) { trigger = "one decision path (adopted)" }
    transition(source = scheduled, target = rejected) { trigger = "one decision path (rejected)" }
    transition(source = scheduled, target = postponed) { trigger = "one decision path (tie or postponed)" }
    transition(source = scheduled, target = withdrawn) {
        trigger = "withdrawMotion"
        guard = "[no active election]"
    }
    transition(source = postponed, target = scheduled) { trigger = "scheduleMotion" }
}
----

== Database safeguards (`V64`)

[cols="2,4", options="header"]
|===
| Safeguard | What it does
| `election.active_motion_id` + `uq_election_active_motion` | Shadow column, equal to `motion_id` while the election is not `ABORTED`, `NULL` otherwise; the unique index allows at most one non-aborted election per motion. A partial unique index (`WHERE status <> 'ABORTED'`) is not available on H2, hence the column. Maintained by `openElection` and `abortElection`.
| `ck_election_active_motion`, `ck_election_active_motion_status` | The column is either `NULL` or the motion id, and `NULL` exactly when the election is `ABORTED`.
| `required_majority_numerator/denominator` + `ck_election_majority_fraction` | Both `NULL` (legacy percent) or `1 <= n <= d <= 100` with `2n >= d`; a half-set pair is refused.
| `ck_election_tally_threshold` | `tally_threshold >= 2` unless the election is `TALLIED` or `ABORTED`. The migration raises running elections with a lower value to 2 first.
| `election_ballot.cast_at` of secret elections | Rewritten to the election's `voting_opened_at` (`COALESCE` with `opened_at`); the application writes the same constant from now on.
| `uq_election_option_position` | Option positions are unique within an election; a second `releaseCandidateList` could only insert duplicates.
|===

The application translates every unique-constraint violation into a `ConflictException` *inside* the transaction block. An
`ExposedSQLException` that escaped the block would make Exposed run the whole block again, including its side effects.

== Ballot secrecy

* `cast_at` of a secret ballot is the constant `voting_opened_at`. The day-coarsened value of V1.9.22 still showed the day and, since
  `listElectionBallots` had no `ORDER BY`, tended to follow the insertion order.
* A secret election lists no ballots before `TALLIED`. The ids were stable from the moment a ballot was cast, so a poll of the list showed
  exactly when a voter's ballot appeared; after the tally the labels of those very ids are revealed. After `TALLIED` the ballots come back
  with a blank id, in an order that depends only on the chosen options.
* The cast result of a secret ballot carries a blank id for the same reason. Ballot ids stay random v4 UUIDs.
* Audited and unchanged: `getElectionParticipation` returns only the caller's own `hasVoted` and counters; `voted_at` is never delivered.

== Single ballots of secret elections are never delivered (V1.9.46)

The rule, owner decision of 2026-10-03: `listElectionBallots` returns `[]` for a secret election -- in every status, at every participation, for every
role. It is the same rule as for an anonymous consensus (V1.9.44), expressed once as `singleBallotsDisclosable(secret)`.

* *One place.* `rpc/ElectionBallotDisclosure.kt` is the only way to a list of `ElectionBallotDto`. `disclosedElectionBallots` decides first
  (`electionSingleBallotsDisclosable`) and short-circuits before any ballot or selection row is read. `ElectionService.listElectionBallots` only delegates.
* *One tripwire.* `ServerElectionDisclosureTripwireTest` pins the single DTO builder, the gate-before-read order, the delegation and an allowlist of the
  files that may read the ballot and selection tables. A new reader must be looked at by a person; it is not added to the list silently.
* *Inventory of readers* (checked by source search): the cast and the receipt check in `ElectionService` (the receipt check returns only the ballot of the
  code, see below), the tally (aggregate only), `ElectionOwnParticipation` (own flags and counters; `member_id` is NULL on a secret ballot), the DSGVO export
  `ElectionPersonalData` (only the member's own named ballots, no selection) and `ElectionTally` (KDoc only). No MCP tool reads election ballots
  (`GetMyBallotsTool` is about governance votes). `getRoomVotingState` returns flags and counters only.
* *No public recount.* Members can no longer recount a secret election themselves. The result counts (`getElectionResult`) and the receipt check
  (`verifyReceipt`) are unchanged. Open-ballot elections keep their named list.
* *No existence oracle.* An unknown or invalid election id answers exactly as before; the secret flag does not change the answer for an existing id.

Residual risks, recorded and not changed in this wave:

* *Small elections.* Resolved in V1.9.53: see "Minimum participation (V1.9.53)" below. The residual risks of that wave are listed there.
* *Receipt as proof.* `verifyReceipt` returns the option label of the ballot to whoever holds the receipt code, from `TALLIED`. A voter can therefore prove
  to a third party how they voted (vote buying, coercion); the election is not receipt-free. Left unchanged by decision; a later option is a check that
  reports only `found` / `counted` without the label.

== Minimum participation (V1.9.53)

*Rule.* A secret election (`secret = true`) with fewer than `DisclosureRules.MIN_ANONYMOUS_RESPONSES` (5) ballots discloses no per-option figures. The
constant is the same as for anonymous polls and anonymous consensus, so the three features cannot drift apart. An open-ballot election is unaffected: its named
ballots are public anyway. The decision (winners, tie, majority) is always made from the full data in `ElectionService.computeOutcome`; only the *disclosure* is
reduced. There is no role exception: BOARD, ADMIN and the election board get the withheld form too, and there is no operator switch.

*Counting.* The number is the rows of `election_ballot` (a ballot is a cast vote, abstention included -- for a yes/no election the abstention is its own option).
It is not the number of eligible voters. There are no invalid digital ballots and no rounds: a runoff is a new election (the motion is postponed). `tally()` runs
exactly once, so the ballot count is frozen when the figures are decided.

*Where it is applied.* In one file on the server: `rpc/ElectionResultDisclosure.kt` (`electionFiguresWithheld`, `disclosedElectionResult`,
`disclosedOptionVoteCounts`, `withheldElectionIds`, `ResolutionDto.withElectionDisclosure`). `ServerElectionResultDisclosureTripwireTest` pins that no other file
builds `ElectionResultDto`, that `ElectionOptionDto.voteCount` only comes from `disclosedOptionVoteCounts` (which decides before it reads the selection table), that
`ResolutionDto` and the `votes*` columns are only handled in `ResolutionBook.kt` (through `toResolutionDtos`), and that `PublicApiResolutionDto` is only built by the
public API routes. `ElectionResultDisclosure.kt` was added on purpose to the ballot-table allowlist of `ServerElectionDisclosureTripwireTest`.

[cols="3,3,4", options="header"]
|===
| Read path | Source | Below the minimum
| `tally()` result, `getElectionResult` | `disclosedElectionResult` | `perOptionVotes` empty, `figuresWithheld = true`, `minimumResponses = 5`; winners, `tie`, `majorityMet` unchanged
| `getElection`, `listElections`, lifecycle RPCs returning `ElectionDto` | `disclosedOptionVoteCounts` | every `voteCount = 0`, `ElectionDto.figuresWithheld = true` (only from `TALLIED`; before the tally the flag is `false`)
| Resolution book: `listResolutions`, `getResolution`, meeting detail, `insertResolutionRow` | `toResolutionDtos` | `votesYes/No/Abstain = 0`, `ResolutionDto.figuresWithheld = true` -- also for rows written before V1.9.53
| Resolution book (write) | `ElectionService.tally` | a YES_NO election below the minimum stores 0/0/0 (people elections and consensus always did)
| Audit log (write) | `auditResolutionCreate` | the snapshot is built from the masked DTO, so new entries hold 0/0/0; the hashed JSON gains no field
| Audit log (read) | `AuditLogService.toAuditLogEntryDtos` | `afterSnapshot`/`beforeSnapshot` of a resolution entry are delivered with zeroed votes and `AuditLogEntryDto.figuresWithheld = true`
| Public API `/api/v1/resolutions[/{id}]` | `ResolutionDto.toPublicApiDto` | `votesYes/No/Abstain = null` (explicit `null`, not omitted), `figuresWithheld = true`
|===

*Negative inventory* (checked by source search, pinned where noted): the webhook `resolution.adopted` is a thin event (only the id; the receiver reads `/api/v1`, covered
above); the MCP tools have no election or resolution tool; PDF, mail and serial letter do not carry vote counts; the DSGVO exports (`GovernancePersonalData`,
`ElectionPersonalData`, `AuditLogPersonalData`) carry no figures or snapshots; `MotionDto` and `PublicApiMotionDto` carry only `resolutionId`; the conference room reads only id,
title, secret flag, status and times of an election (`ConferenceService`). The participation line "x of y" (`ElectionParticipationDto.ballotCount`) stays visible, like
`ballotCount`/`eligibleCount` for consensus.

*Client.* `renderElectionResultCompact` decides on `result.figuresWithheld` first. The withheld form lists the options of a people election by *position* (never by
votes -- the order must not tell a ranking), marks the winners, shows the verdict and one sentence ("Aus Gründen des Wahlgeheimnisses ...", only when at least one ballot
exists), and has no figure, no bar and no `aria-valuenow`. A yes/no election shows no option rows at all. The normal path now also orders by position. The client never infers
"withheld" from `voteCount == 0` (`ElectionSecrecyTripwireTest`). The resolution book row, the audit log detail and the open form ("Geheime Wahl" help line) show the rule.

*Residual risks and limits* (recorded, not changed in this wave):

* *E1, the decision itself.* The outcome is public: with a tie, `tie` and the missing winner say that the votes were level; with a unanimous result from five ballots on, every
  vote is known. Five is a deliberately small constant shared with polls.
* *E2, small groups.* Five ballots can still be five identifiable people; the rule hides the figures, not the group size (`ballotCount` stays visible).
* *E3, the verdict leaks a bound.* "Majority reached" for a yes/no election below five ballots tells that more than half of the yes/no votes were yes.
* *E4, receipt as proof.* `verifyReceipt` still returns the own option label (unchanged, see above).
* *E5, database and backups.* The tables `election_ballot_selection` and `resolution` still hold the real figures (a Legacy resolution row also keeps its stored numbers; only the
  delivery is masked). Whoever has database access sees them.
* *E6, audit hash and masked entries.* Entries written before V1.9.53 are masked when read, so the delivered `afterSnapshot` no longer matches the stored `entryHash`
  (flagged by `AuditLogEntryDto.figuresWithheld`). The server-side `verifyChainIntegrity` reads the raw rows and stays valid; an external verifier that hashes the delivered
  snapshot of such an entry cannot reproduce the hash. New entries are written masked, so they verify. *Honest limit:* the hash fields are still delivered, so a reader with
  an audit role (TREASURER, BOARD, ADMIN) can recover the figures of such an old entry by brute force (fewer than 5 ballots: at most 35 candidate triples, one SHA-256 each).
  Withholding `entryHash` would not help, because the next entry's hash covers it as `previousEntryHash`. Entries written since V1.9.53 store 0/0/0 and offer no oracle.
  A snapshot that cannot be decoded is withheld (`null`), never delivered unmasked. Closing the gap for old data would need a data migration that rewrites the chain; not planned.
* *E7, organisation export.* The complete organisation export (`OrganizationExportService`, ADMIN only, database dump) contains `resolution`, `audit_log_entry` and
  `election_ballot*` unmasked: it must stay lossless and restorable (right to secede), the same level as database access.

== Known limitations and follow-ups

* `resolveMotion` is not refused while a meritocratic vote or a systemic consensus is open (only the election blocks it). That would
  change existing behaviour and is a separate decision.
* Specific conflict codes in the RPC (today every refusal is a `ConflictException`).
* Who released the tally is visible only as a count.
* The concurrency tests run on H2 AND, since V1.9.37, on a real PostgreSQL (the Postgres test lane, link:postgres-test-lane.adoc[postgres-test-lane.adoc]);
  the lock order of this document is measured there, including all decision paths racing on one motion.
* `castVoteBallot` and `castResistanceBallot` have their own races against closing; they are outside this wave.
* Amendments to a motion that has a running election.
