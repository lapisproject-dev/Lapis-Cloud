= Secrets from files: `<NAME>_FILE` (V1.9.266)
:toc:

== Purpose

Until V1.9.265 every secret had to be an environment variable. An environment variable is visible in `docker inspect`, in
`/proc/<pid>/environ` and in every crash report that dumps the environment. V1.9.266 lets an operator hand a secret over as a
file instead (Docker/Compose secrets under `/run/secrets`, Swarm secrets, Kubernetes secret volumes).

*The default does not change.* Without a `<NAME>_FILE` variable every secret is read from `<NAME>` exactly as before, byte for
byte. No operator action is required.

== Which variables

18 variables accept a `_FILE` companion (`SecretEnv.SECRET_NAMES`): `LAPIS_DB_PASSWORD`, `LAPIS_SECRET_ENCRYPTION_KEY`,
`LAPIS_SMTP_PASSWORD`, `LAPIS_MAILING_TRACKING_KEY`, `LAPIS_KEYCLOAK_CLIENT_SECRET`, `LAPIS_LIVEKIT_API_KEY`,
`LAPIS_LIVEKIT_API_SECRET`, `LAPIS_TURN_SHARED_SECRET`, `LAPIS_STRIPE_SECRET_KEY`, `LAPIS_STRIPE_WEBHOOK_SIGNING_SECRET`,
`LAPIS_PAYPAL_CLIENT_SECRET`, `LAPIS_AI_API_KEY`, `LAPIS_LETTERXPRESS_APIKEY`, `LAPIS_BOOTSTRAP_ADMIN_PASSWORD`,
`LAPIS_STAGING_SEED_PASSWORD`, `LAPIS_ORACLE_ALPHAVANTAGE_KEY`, `LAPIS_ORACLE_GOLDAPI_KEY`, `LAPIS_ORACLE_METALPRICEAPI_KEY`.

Identifiers that are not secrets (user names, client IDs, webhook IDs) are deliberately not on the list. Do not embed a password
in `LAPIS_DB_URL` (JDBC parameter `password=`); use `LAPIS_DB_PASSWORD_FILE`.

== Rules

. `<NAME>_FILE` empty or blank counts as not set.
. `<NAME>` empty or blank counts as not set when `<NAME>_FILE` is set (Compose passes optional values as `${X:-}`, i.e. set but
  empty).
. `<NAME>` non-empty and `<NAME>_FILE` set: startup fails (ambiguous).
. The path must be absolute. Symbolic links are followed (Kubernetes uses a `..data` chain); the final target must be a regular
  file. A directory, FIFO or device is rejected before it is opened, so it cannot block the start.
. At most 64 KiB; the file must be valid UTF-8, must not start with a byte order mark and must not contain a NUL byte.
. Exactly one trailing line break (`\n` or `\r\n`) is removed. Nothing else is trimmed. A file that is empty (or only a line
  break) is an error. The configuration classes trim exactly as they do for the same value in the variable.
. The file is opened with `NOFOLLOW_LINKS` after the path was resolved, and its attributes (file key, modification time, size) are
  compared before and after reading; a change fails the start (`CHANGED`).

== Failure behaviour (fail closed)

Every problem throws `SecretFileException`. The message is `"<VAR>_FILE: <reason>"` only: never the path, never a value, never a
cause (an `IOException` message contains the path). `SecretEnv.preflight()` is the first statement of every `main()` and
resolves all 18 names eagerly, so a broken file stops the start even when the secret would be read late or inside a
`catch (Exception)`. Nobody may catch `SecretFileException` and treat it as "not configured".

On success exactly one INFO line per name is written: `Secret <NAME> read from file (<NAME>_FILE)`.

== Rotation and memory

Resolved values are cached for the process lifetime. There is no file watcher and no reload: *rotation means restart*. The byte
and character buffers are overwritten after reading, which is best effort only; the resulting `String` stays in memory like any
secret read from an environment variable. Heap dumps contain secrets: do not hand heap dumps to third parties, and write
`-XX:+HeapDumpOnOutOfMemoryError` dumps only to protected directories.

== Residual risk

Java has no `fstat` on an open channel and no `O_NONBLOCK`. Someone who can replace the target between the attribute check and
the open can swap in a FIFO and block the start. That requires write access to the secret directory, which already means access
to the secret.

== One gateway for every environment read

All environment reads go through `SecretEnv.get` (or a `env: (String) -> String?` parameter defaulting to `SecretEnv::get`).
`SecretEnvTripwireTest` enforces:

* `getenv` appears in the production sources only in `SecretEnv.kt`;
* every `LAPIS_*` literal that looks like a secret (`PASSWORD`, `SECRET`, `API_KEY`, `_KEY`, `TOKEN`, ...) is on the list or on a
  commented allowlist;
* every list entry is still used;
* `_FILE` literals and `SecretFileException` exist only in `SecretEnv.kt`;
* `SecretEnv.preflight()` is the first statement of each `main()`.

A new secret therefore goes into `SecretEnv.SECRET_NAMES`.

== Not covered

LiveKit, coturn and egress receive their secrets through `render-secrets.sh` templates and keep needing the plain values there.
Whoever switches `LAPIS_LIVEKIT_*` to `_FILE` must still provide the values to `render-secrets.sh`. See
link:logging-privacy.adoc[logging-privacy.adoc] for what the logs may contain.

== Verification status
