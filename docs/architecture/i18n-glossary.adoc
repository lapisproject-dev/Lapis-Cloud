= i18n Glossary -- Fixed Terms of the Client (V1.4.31, W5)
:toc:

== Purpose

The client is translated into seven languages (`en es fr it nl pl ru`), the German text is the msgid. Legal, accounting and
governance terms must read the same in every place they occur: a member who sees "Antrag" as "motion" on one screen and as
"application" on the next reads two different concepts. This glossary fixes the accepted rendering of each core term per language.

It is not only prose. `I18nGlossaryConsistencyTest` (`lapis-server`) reads the table below and checks the real catalogs:
for every German msgid that contains a core term as a whole word (or one of its listed inflected forms), each of the seven
`msgstr` must contain at least one *accepted stem* of that language. A collision turns the build red.

== How the table is read

* *German forms* -- the msgid forms that trigger the check, comma separated. A form only matches as a whole word: `Beitrag`
  matches "Beitrag boosten" and "Kein Beitrag", but neither `Beitragssatz` (a compound) nor `Beiträge` (not listed).
* One column per language with the *accepted stems*, comma separated, compared case-insensitively as substrings of the
  translation. A stem is deliberately short (`contribut`, `składk`) so that inflected forms match.
* A term with two meanings lists the stems of BOTH meanings in the same cell; the notes column names them. Adding a stem for a
  new meaning is a decision that belongs in the pull request, not in the test.

== Known gaps

* The homonym "Stornieren": in the accounting screens it means to reverse a posting; in the event screens it stands for cancelling a
  registration or a shift. The catalog carries ONE msgid for both. Resolving it needs a new msgid for the event meaning
  ("Veranstaltung absagen" and the like already have their own); the remaining event occurrences are not split in W5.
* Only whole words are checked. Compounds ("Beitragssatz", "Spendenquittung") and plural forms that are not listed are not covered.
