= Voting in the conference room, server query and nudge channel (V1.9.24)
:toc:

== Purpose and scope

Wave 1 of four that bring voting into the video conference. This wave has **no user interface**. It adds the two building blocks the
later waves stand on:

* `IConferenceService.getRoomVotingState(roomId)`, a server query that tells a participant which ballots of the room's Sitzung are
  running or just finished, and what the caller's own status in each is.
* The data-channel topic `lapis-vote-nudge`, a data-less signal that makes the other clients ask the server again, so the list
  updates within about two seconds instead of at the next 5-second poll.

Wave 1 delivers democratic elections only. Meritocratic votes follow in V1.9.27 (section "Client: the meritocratic vote in the room",
below); systemic consensing got its own screen in V1.9.28 (`consensus-ui.adoc`) but is not part of the room, its enum value `CONSENSUS` is reserved and never filled. The room screen (V1.9.25)
and the operator panel (V1.9.26, below) follow.

NOTE: This document's `[kuml]` blocks are rendered and validated by the `:docs-render:renderDocs` Gradle task.

== Data flow

The server is the single source of truth. The nudge only says "look again"; it never carries a ballot, a title or a result.

[source,kuml,name="conference-voting-dataflow"]
----
sequenceDiagram(name = "Room voting state and nudge") {
    val operator = lifeline(name = "Operator client")
    val channel = lifeline(name = "LiveKit data channel (P2P, untrusted)")
    val peer = lifeline(name = "Participant client")
    val server = lifeline(name = "ConferenceService (server authoritative)")
    val db = lifeline(name = "conference_room, election, own-flag tables")

    message(from = peer, to = server, label = "getRoomVotingState(roomId) every ~5 s")
    message(from = server, to = db, label = "room -> meeting_id (session-derived, never a parameter)")
    message(from = server, to = db, label = "active elections, then recently tallied, max 20")
    message(from = server, to = db, label = "own eligible / has-voted flags, at most 3 queries")
    message(from = server, to = peer, label = "RoomVotingStateDto (own flags only) | uniform Forbidden")
    message(from = operator, to = channel, label = "after openVoting / closeVoting / tally: lapis-vote-nudge, one zero byte")
    message(from = channel, to = peer, label = "payload is DISCARDED, never read")
    message(from = peer, to = server, label = "at most one extra getRoomVotingState per 2 s")
}
----

== Authorization and the uniform error

The meeting is derived on the server from `conference_room.meeting_id`; the client never names a Sitzung. The caller must pass the
shared room-entry gate (`requireRoomEntryAuthorization`: member status, and for non-members the room's `allowFederationGuests`)
**and** have an open `conference_participation` row in the room. The second condition applies to every role, including the room
creator: only a client that is actually in the room polls.

Every denial throws the same `ForbiddenException` with the same message (`ROOM_VOTING_UNAVAILABLE`):

* unknown room id, an id of a room the caller is not in, an ended room,
* a breakout room id or a breakout LiveKit room name (they are not `conference_room` rows),
* a caller who left or was removed (`left_at` is set), a withdrawn member, a friend or guest of a room without guest access,
* a malformed id.

The participation lookup runs even for an unknown room so the denial paths do the same work. Only `ForbiddenException` and
`NotFoundException` are mapped; a rate-limit error (`Conflict`) and "conference not configured" (`Conflict`) keep their own type.
`listParticipants` answers an unknown room with `NotFound` and a foreign room with `Forbidden`; that is an existence oracle, and this
query deliberately does not copy it.

The query has its own rate budget, 90 requests per member and minute (`roomVotingStateRateLimiter`, a module-scoped singleton, no
constructor default). Sharing the list limiter would let polling starve `listParticipants`.

== Status filter and caps

[cols="2,1,4", options="header"]
|===
| Election status | Delivered | Why
| `PREPARATION`, `CANDIDATE_LIST_RELEASED` | no | Nothing can be done in the room yet, and before the snapshot the eligibility is unknown (a three-valued flag). The election list and the operator panel use `ElectionService` directly.
| `OPEN` | yes, `OPEN` | The member can vote.
| `CLOSED` | yes, `CLOSED_AWAITING_TALLY` | Voting is over, the count is awaited.
| `TALLIED` within 12 hours | yes, `DECIDED` | The result is still relevant for the running meeting. After that it is not.
| `ABORTED` | no | Nothing to show.
|===

At most 20 ballots are delivered (`truncated` says when the cap applied). Active elections are read first and recently tallied ones
second, so a tallied election never pushes out an open one. Order: `OPEN`, `CLOSED_AWAITING_TALLY`, `DECIDED`. At most five queries
run regardless of the number of ballots.

== Ballot secrecy

`RoomBallotDto` carries only the caller's own flags (`ownEligible`, `ownHasVoted`). It has no counters, no timestamps, no choice, no
receipt, and no names or member ids. The shared helper `ElectionOwnParticipation` keeps the table separation exactly as it was:
for a secret election "has voted" comes from `election_participation`, for an open one from `election_ballot`.
`ElectionService.getElectionParticipation` uses the same helper. A non-member is never eligible: `ownEligible` is forced to `false`
even if a snapshot row existed.

== Breakout rooms

Breakouts are `conference_breakout_room` rows. A participant's main-room participation stays open during a breakout excursion, so the
client asks with the **main** room id and sees the main room's Sitzung. No special logic exists. A breakout id is simply denied.

== The nudge channel and its trust boundary

Topic `lapis-vote-nudge`, one zero byte, reliable. Any room participant can publish anything on any topic, so the receiver treats
the signal as untrusted: it does not decode, parse or read the payload or the sender, it only triggers `onVoteNudge`, throttled by
`VoteNudgeThrottle` to one call per 2 seconds (leading edge immediately, exactly one trailing call for anything inside the window, so two
closely spaced events are not lost). The only allowed reaction is an authorized server query. A forged nudge costs at most one extra,
rate-limited `getRoomVotingState` call. The throttle timer is cancelled on `disconnect()`.

== Secret-ballot stream pause: findings

[cols="1,4", options="header"]
|===
| Finding | Result
| C1, hanging pause | A stream stuck in `PAUSING` can always be left: `stopStream` needs only the room moderator or a privileged account and sits outside `SecretBallotStreamLock`; `abortElection` needs only the election manager. Both are covered by tests in `SecretBallotStreamPauseTest`. Until the egress is confirmed stopped, a ballot stays rejected (`STOPPING` blocks like `PAUSING`), then the poller ends the stream and the ballot is castable again. Gap: a room moderator without an election role can unblock the vote by stopping the stream but cannot abort the election.
| C2, unbound room | A room without a bound Sitzung is never paused when a secret election opens, because only rooms bound to the meeting are checked. The test `knownGap_unboundRoomStreamIsNeverPaused` documents this behavior; it is not a tripwire and changes together with the later wave that changes the behavior.
|===

== Known limitations

* Client: a CONSENSUS ballot (reserved, never delivered) would show only its state. Since V1.9.27 a VOTE has its own card, bid view and operator controls (below).
* In-app navigation (menu, hash) during a visible receipt discards it, exactly as on the elections page.
* The nudge does not reach participants in breakouts; the poll covers them.
* Leaving while a ballot request is in flight is blocked since V1.9.26 (the `CASTING` lock, see below); closing the browser tab asks first.
* Elections and meritocratic votes; consensing is not yet in the room panel (a later wave).
* Unbound room: stream is never paused (C2).
* A hanging pause can be resolved only by the room moderator or the election management (C1).
* Recordings are not paused for a secret ballot; the room banner says so (V1.9.26).
* A small timing difference between "unknown id" and "known id" remains (ids are random UUIDv4, low risk).

== Untrusted free text

`title` (election) and `motionTitle` (motion) are member-authored. The server returns the raw text. The client (V1.9.25) renders both
only through `untrustedP`/`untrustedSpan` and, for the screen-reader announcement, `sanitizeUntrustedI18nText`; there is no
`innerHTML` and no `.content = dto.field`. This closes the review point of V1.9.24.

== Client: the room voting panel (V1.9.25)

Wave 2 of four, client only. The server is unchanged and no migration exists. All ballot code is in one file,
`ConferenceVotePanel.kt`, which `ElectionSecrecyTripwireTest` watches; `ConferenceScreen.kt` holds only the wiring.

=== Components and data flow

`ConferenceVotePollController` asks `getRoomVotingState` (every 5 s while a ballot is open or awaiting its count, 15 s otherwise,
30 s in a hidden tab, at once when the tab becomes visible). The data-channel nudge calls `nudge()`, which asks at once but never
more often than once per second; at most one request is in flight and whatever arrives meanwhile becomes exactly one follow-up.
The pure `voteRoomReduce` turns the answer into a state, the list of newly opened elections and a `listChanged` flag. A failed
poll only counts; after three misses in a row a calm "status is being updated" line appears, never an error text.

The panel `ConferenceVotePanel` shows one card per election (title, state, your own standing, one primary button only when you can
still vote). It embeds the real booth (`ElectionBooth`, with a banner for open ballots) instead of a copy. The panel state (`normal`/
`fullscreen` flags, narrow-screen exclusion with chat, the rail share, the lock) lives in the existing `conferencePanelReduce`.

=== The quiet rule

A poll answer rebuilds only the overview, and only when the list changed. While the booth is open the overview is hidden and the
booth's container is never touched. A new election opens the panel at most once per election id, never on a narrow screen, never
under a lock, never for an election that was already open when the call started (those only show in the badge); the screen-reader
announcement through a live region outside the panel always comes and never moves the focus.

[source,kuml,name="conference-voting-client-state"]
----
stateDiagram(name = "Room voting panel") {
    val start = initialState()
    val closed = state(name = "Closed")
    val overview = state(name = "Overview")
    val booth = state(name = "Booth")
    val receipt = state(name = "Receipt on screen")

    transition(source = start, target = closed)
    transition(source = closed, target = overview) { trigger = "toggle, or a new election opens (wide screen, once per id)" }
    transition(source = overview, target = overview) { trigger = "poll answer (list rebuilt only if it changed)" }
    transition(source = overview, target = booth) {
        trigger = "Zur Wahlkabine"
        guard = "[open, eligible, not voted yet]"
    }
    transition(source = booth, target = receipt) {
        trigger = "ballot cast"
        guard = "[secret election]"
    }
    transition(source = booth, target = overview) { trigger = "back, cancel, or an open ballot is done" }
    transition(source = booth, target = booth) { trigger = "close panel (blocked)" }
    transition(source = receipt, target = overview) { trigger = "Fertig (receipt noted)" }
    transition(source = receipt, target = receipt) { trigger = "close panel, leave, end for all, back to main room (blocked)" }
    transition(source = overview, target = closed) { trigger = "toggle, Esc" }
}
----

=== The receipt and leaving the page

The receipt code exists only in the two DOM nodes of the booth. The panel learns one Boolean ("a receipt is on screen") through
`electionReceiptVisibilityHook`, which `ConferenceReceiptHookScope` takes for the panel's life and gives back, keeping a hook somebody
else set in the meantime. While the receipt is up the panel cannot be closed, and "Verlassen", "Für alle beenden" and "Zurück zum
Hauptraum" are disabled and say why (each of them disconnects).

The old unload listener disconnected on `beforeunload`, which fires before the browser asks "leave this page?". With a receipt the booth
asks, and answering "stay" left the member in the page but out of the room. `ConferenceUnloadGuard` now disconnects on `beforeunload`
only without a receipt and always on `pagehide`, which fires only when the page really goes.

=== Roles and rooms

The panel and its toggle exist only for an active member; a guest or friend gets one status line while ballots are running, and the
controller still runs for them. A room without a Sitzung shows no toggle; the moderator sees a hint next to "Sitzung zuordnen".
Breakouts ask with the main room id, as documented above.

== Client: operator controls and secret-ballot wiring (V1.9.26)

Wave 3 of four, client only. The server is unchanged and no migration exists: every RPC the operator side needs already exists
(`openVoting`, `closeVoting`, `approveTally`, `tally`, `abortElection`, `getElection`, `getElectionParticipation`,
`getElectionResult`, `listElections`, `stopStream`). The new code lives in `ConferenceVoteStreamMirror.kt` (pure, no DOM, no RPC) and
`ConferenceVoteOperatorControls.kt`; `ConferenceVotePanel.kt` and `ConferenceScreen.kt` only wire them in.

=== Roles: the gates are the server's

Every gate comes from `ElectionAuthzUi`, the mirror of the server's rules; the operator side never decides a permission itself.

[cols="2,3", options="header"]
|===
| Action | Who (as the server decides)
| Open, close, count | An appointed election board member, or BOARD/ADMIN
| Approve the count | A real election board member only (BOARD/ADMIN have no bypass; the N-of-M count is of named members)
| Abort | The committee leadership of the motion, or BOARD/ADMIN ("manage"); needs the motion and the roster, so it is read lazily
|===

Deviation from the original brief, stated openly: the committee leadership (without election board seat or BOARD/ADMIN) can open and close
nothing, because the server does not allow it. In the room it gets exactly its own right: "Wahl abbrechen" on the emergency card.
Letting it open and close would be a server rule change that touches the four-eyes model and is not part of this wave.

=== Where "prepared elections" come from

`getRoomVotingState` lists only OPEN, CLOSED and TALLIED elections, so an election that is still being prepared never reaches the room.
The panel therefore reads `listElections(status = PREPARATION)` and `listElections(status = CANDIDATE_LIST_RELEASED)` and keeps those of
the room's Sitzung (client-side filter on `meetingId`, at most 10, each with one participation read for the gate). The calls are
organisation-wide and unpaginated; the status filter keeps them small, and they run only while the panel is open and the room is bound:
on opening, when the tab becomes visible, at most every 30 s with the poll rhythm, and after the member's own actions. A server query
`listRoomPreparedElections(roomId)` would be cleaner but is not necessary and stays an option.

=== The stream mirror

The server refuses a secret ballot while a stream of the Sitzung is publishing (`requireStreamQuiescedForBallot`, over all rooms of
the Sitzung). The client mirrors that table to show the lock early; the server stays the authority.

[cols="1,1,3", options="header"]
|===
| Stream status | Lock | Note
| `PAUSED`, `ENDED`, `FAILED` | free | `FAILED` frees, too
| no stream known | free |
| `STARTING`, `LIVE`, `STOPPING` | locked |
| `PAUSING` | locked, after 20 s "slow", after 60 s "hung" | the stopwatch starts at the first observation of `PAUSING`
|===

`ConferenceVoteOperatorTripwireTest` parses the server's private `isQuiescedForBallot` and the
client's `quiescedForSecretBallot`, compares their "free" sets, requires both to be exhaustive without `else`, and requires both to name
every status. A new status is a compile error on each side until a human decides.

[source,kuml,name="conference-voting-stream-mirror"]
----
stateDiagram(name = "Cast lock of a secret ballot") {
    val start = initialState()
    val free = state(name = "FREE")
    val locked = state(name = "LOCKED (stream pausing)")
    val slow = state(name = "LOCKED_SLOW (after 20 s)")
    val hung = state(name = "HUNG (after 60 s)")

    transition(source = start, target = free)
    transition(source = free, target = locked) { trigger = "stream STARTING, LIVE, PAUSING or STOPPING" }
    transition(source = locked, target = slow) { trigger = "20 s of PAUSING" }
    transition(source = slow, target = hung) { trigger = "60 s of PAUSING" }
    transition(source = locked, target = free) { trigger = "stream PAUSED, ENDED or FAILED" }
    transition(source = slow, target = free) { trigger = "stream PAUSED, ENDED or FAILED" }
    transition(source = hung, target = free) { trigger = "stream PAUSED, ENDED or FAILED, or stopped by the moderation" }
}
----

A conflict is the normal way to learn that the mirror was wrong: the Sitzung may have a stream in ANOTHER room, which the client of this
room never sees, and a breakout never knows its own stream. The booth then treats a conflict as "still locked", not as an error: if
the probe says the election is still OPEN and the member has not voted, the selection is kept in the booth controller's memory (never in
the DOM outside the booth and never in a storage), the cast button stays disabled with a visible reason, and after 5 s it is enabled
again. There is no automatic re-submit. Without the lock hook (the elections page, every open election) nothing changes: a conflict ends
in the terminal text as before.

For members `HUNG` reads as `LOCKED_SLOW`; only the operators and the moderation get the emergency card.

=== Polling the stream

`LIVE` is pushed over LiveKit, not polled, so without a change the booth could stay on `LIVE` after the server has started pausing. While
a secret ballot is open and the stream is not quiesced, the stream status is therefore polled every 5 s (at most 12 of the 60 allowed
reads a minute); otherwise the old 15 s rhythm applies. The two time stages (20 s, 60 s) are driven by a timer in the panel, because no
push announces them.

=== Operating an election

[source,kuml,name="conference-voting-operator-sequence"]
----
sequenceDiagram(name = "Opening a secret election from the room") {
    val operator = lifeline(name = "Operator client")
    val server = lifeline(name = "ElectionService (server authoritative)")
    val streams = lifeline(name = "Streams of the Sitzung")
    val peer = lifeline(name = "Participant client")

    message(from = operator, to = operator, label = "dialog: stream state, other rooms, recording stays on")
    message(from = operator, to = server, label = "openVoting(electionId), once (double-click guarded)")
    message(from = server, to = streams, label = "pause every stream of the Sitzung (PAUSING, then PAUSED)")
    message(from = server, to = operator, label = "ElectionDto (OPEN)")
    message(from = operator, to = peer, label = "lapis-vote-nudge, one zero byte (only after success)")
    message(from = peer, to = server, label = "getRoomVotingState, then the stream status every 5 s")
    message(from = peer, to = peer, label = "cast button locked until the stream is PAUSED, then free")
}
----

One guarded function, `runOperatorAction`, is the only place in the operator side that writes. It runs through `runGuardedAction`
(a second click while the first runs does nothing), answers a `ConflictException` with the neutral "the state changed and was reloaded"
(its message is never read; what it meant is found out by reloading), and reloads the room, the counters and the prepared list afterwards.
Only after a successful open, close, tally or abort does it send the nudge, once; approving sends none (the other operators see the new
count with their next poll, which refreshes the counter of a CLOSED election every 5 s while the panel is open). A lost nudge is
ignored without any message: the other clients catch up with their poll.

* One primary button per status: open (prepared elections), close, approve or count. Closing, counting and aborting ask first; the
  dialog focuses "Abbrechen", names the verb on the action button and, at zero ballots, adds "Es wurde noch keine Stimme abgegeben.".
  Aborting needs the election title typed, exactly as on the elections page.
* Opening a secret election shows what happens first: the stream of this room, that streams of other rooms of the Sitzung are paused
  as well, and that the recording is not paused.
* An operator who opens the booth to vote loses the controls next to the ballot and reads why; they return with the overview.
* The count of a TALLIED election is shown with the same rows as the detail page (`renderElectionResultCompact`).

=== The banner

The existing banner above the call now speaks for the whole secret ballot ("Geheime Wahl läuft: ..."), with the stream state and, unless
the recording is known to be off, the sentence that the recording goes on. It is a polite status (a changed text is not re-announced
as an alarm), has no close button and lives in the call surface, so a guest sees it too; a guest without room state sees it only for a
stream that is being paused for a ballot.

=== Casting is not interruptible

While the ballot request is in flight the panel lock is `CASTING`: the leave buttons are disabled with the reason "Ihre Stimme wird gerade
übermittelt", the unload guard treats it like a visible receipt, and the browser's own "leave this page?" question is registered only for
that time (the receipt of that very request would have no place to appear once the page is gone). `pagehide` still always disconnects.

== Client: the meritocratic vote in the room (V1.9.27)

Wave 4 of four. The room shows a meritocratic vote (a vote with LTR bids, `Vote` in the governance code) next to the elections, lets an
eligible member place a FIRST bid, and lets the person who may record for the committee open a Yes/No vote and close a running one.

=== Server: what the room learns about a vote

`getRoomVotingState` now also delivers `RoomBallotKind.VOTE` ballots. Everything else about the query (authorization, the uniform
error, the rate limit, the lock on the motion) is unchanged.

|===
| Vote state | Room status | Delivered
| `OPEN` | `OPEN` | yes
| `CLOSED`, closed within the last 12 hours | `DECIDED` (the result is computed while closing, `CLOSED_AWAITING_TALLY` never occurs for a vote) | yes, with `winnerOptionId` (`null` on a tie)
| `CLOSED`, older | | no
| `ABORTED` | | never
|===

* **One ranking, one cap.** All open elections and votes come first, then elections in `CLOSED`, then ended ballots (tallied elections
  and closed votes), newest first; the cap of 20 is shared, so an ended ballot of either kind never displaces an open one. The number of
  queries does not depend on the ballot count.
* **Fields.** A vote carries `options` (`id`, `label`, `position`, ordered by position) and, once decided, `winnerOptionId`.
  The DTO NEVER carries a basket total, a stake, a settlement, the second price, a name, a timestamp, the caller's own stake or any
  count of bids. The server reads only `vote_ballot.vote_id` of the caller's own rows and never selects `second_price_ltr`.
* **Eligibility** is the rule of `castVoteBallot`: the status must be in `MemberStatusSets.ORGANIZATION_MEMBER` and the member must be in
  the eligible set of the vote's Sitzung. The polling path uses `isCommitteeEligible`, the point-access twin of `eligibleMemberIds`
  (same conditions, plus `member_id`), so a general assembly does not load every active member every five seconds. A parity test pins
  both against each other; `castVoteBallot` itself still uses `eligibleMemberIds`.
* **Never secret, never pauses the stream.** A meritocratic vote is saved by name (`secret = false`); `SecretBallotStreamLock` does not
  know it, so it neither pauses a stream nor blocks unbinding the room.
* No migration: the existing indexes serve the queries (`vote(meeting_id)` is not indexed; the table is small and the query is limited).

=== Client: card, bid view, operator

----
sequenceDiagram(name = "A first bid and closing the vote from the room") {
    val member = lifeline(name = "Member client (panel)")
    val server = lifeline(name = "Server (authoritative)")
    val ledger = lifeline(name = "LTR ledger")
    val operator = lifeline(name = "Operator client")

    message(from = member, to = server, label = "getRoomVotingState (fresh, before the bid view opens)")
    message(from = member, to = member, label = "dialog: stake, option, 'bound immediately'")
    message(from = member, to = server, label = "castVoteBallot(createOnly = true)")
    message(from = server, to = ledger, label = "VOTE_STAKE debit (refused with a Conflict if a bid exists)")
    message(from = member, to = operator, label = "lapis-vote-nudge, one zero byte")
    message(from = operator, to = operator, label = "dialog: close the vote, focus on Abbrechen")
    message(from = operator, to = server, label = "closeVote(voteId)")

* **Card** (`ConferenceMeritVoteCard.kt`): title, "Meritokratische Abstimmung", the state, "offen – namentlich", your standing ("Sie haben
  geboten" / "Sie sind stimmberechtigt" / "Nicht stimmberechtigt"). One primary button "Gebot abgeben" only for an eligible member without
  a bid; a link "Gebot ansehen oder ändern" (new tab, `rel="noopener noreferrer"`) once a bid exists; for a decided vote "Ergebnis: <label>"
  or "Unentschieden – kein Gewinner" and "Ergebnis im Detail". A winner id that is not among the options shows no result line. The notice
  "Diese Abstimmung ist offen und wird namentlich gespeichert" appears once above the open cards. Titles and labels go through the
  untrusted-text helpers.
* **Bid view** (`ConferenceMeritBidView.kt`) lives in the SAME booth host as the election booth, so the panel's close lock, the "no
  auto-open while it is open" rule and the unload prompt apply without new state. Before it opens, the panel asks the server again
  (`getRoomVotingState`): a vote that is no longer open or a bid that already exists means a note and no bid view. It shows the free
  balance (the shared load states: a failure shows the one error sentence with a retry) and the honest explanation of what a stake does.
  Sending asks once ("%1 LTR auf „%2“ setzen? ...") and goes through the same form as the motion page (`VoteBallotForm.kt`).
* **`createOnly`.** `VoteBallotInput.createOnly` (default `false`) makes `castVoteBallot` throw `ConflictException` when the caller already
  holds a ballot, checked after the debit lock and before any ledger write. The room sets it, so a stale card can never turn a first bid
  into a silent recast; the motion page keeps the old behaviour exactly. A conflict returns the member to the list with the fixed note
  "Der Stand hat sich geändert und wurde neu geladen."; the exception's message is never read.
* **Operator** (`ConferenceMeritVoteOperator.kt`). The gate is `GovernanceAuthzUi.canRecordForMeeting` (board or admin, or CHAIR, DEPUTY_CHAIR
  or SECRETARY of the target committee), the mirror of the server's rule; the room moderation (`canModerateRoom`) is NOT consulted.
  "Ja/Nein-Abstimmung eröffnen" appears under the prepared items for a SCHEDULED motion of this room's Sitzung that `meritCanOpen`
  accepts: no open or finished vote, no running election, no consensus unless aborted, and no pending amendment (`openVote` does not
  check amendments but `closeVote` does, so a vote opened over a pending amendment could not be closed). At most five candidates are looked
  at, re-read every 30 seconds, after an own action and when the panel opens. "Abstimmung schließen" sits on the card of a running vote and
  asks first (the dialog focuses "Abbrechen"). Aborting a vote, custom options and changing a bid stay on the motion page.
* **The options are the literals `YES` and `NO`, never translated.** `closeVote` decides the outcome by the label text: the label "NO"
  (case-insensitive) means REJECTED, any other winning label means ADOPTED. A translated "Nein" would turn a rejection into an adoption.
  A tripwire pins the literals.
* **Writes.** Opening and closing go through the controller's one guarded function `runOperatorAction`; a tripwire pins it for the merit
  operator as well.

=== Known limitations (V1.9.27)

* **Stakes stay bound.** `castVoteBallot` debits the stake immediately as `VOTE_STAKE`, and no path releases it afterwards: neither
  `closeVote` (it only sets `settledLtr`), nor `abortVote`, nor a lower recast. The room therefore says so ("... bleibt gebunden ... eine
  Rückgabe nicht verbrauchter Beträge gibt es derzeit noch nicht") and never promises a refund. A release path needs a new ledger type,
  a settlement and a migration: a project of its own.
* The room never loads other members' bids; a changed bid, custom options and aborting a vote are on the motion page (new tab).
* The text "Kein Gewinner, keine Belastung" on the motion page (`renderVoteSection`, tie) is inexact for the same reason; it is outside this wave.
* The staging test (`conference-voting-staging-test.adoc`) was written but not run: the credentials belong to the operator.

== Systemic consensus in the room panel (V1.9.32)

The systemic consensus ("Konsensieren", V1.9.28) is now part of the room panel: a card per consensus, the resistance booth embedded in
the same booth host, and the operator steps freeze, close, evaluate and "rate again". The screen and its booth are described in
`consensus-ui.adoc`; this section is only what the room adds.

=== Server: what the room learns about a consensus

`RoomBallotDto` gets ONE additive field, `consensusPhase` (`null` for elections and votes), and `RoomBallotKind.CONSENSUS` is filled. No
new enum value, no migration (`systemic_consensus` already carries `meeting_id`, `round`, `rating_opened_at`, `rating_closed_at` and
`tally_run_at`), so a client of an older version keeps working.

The phase maps onto the neutral `RoomBallotStatus`; the real phase travels in `consensusPhase`:

[cols="2,2,3",options="header"]
|===
|Consensus phase |`RoomBallotStatus` |In the list
|`COLLECTION`, `RATING` |`OPEN` |always
|`CLOSED` |`CLOSED_AWAITING_TALLY` |always
|`EVALUATED` |`DECIDED` |only while `tally_run_at` is inside the recently-decided window
|`ABORTED` |never delivered |--
|===

* **Allowlist.** The query selects only `id`, `title`, `status`, `secret`, `round`, `motion_id`, `opened_at`, `rating_opened_at`,
  `rating_closed_at`, `tally_run_at` and the motion title. `winner_option_id`, `opened_by`, `resolution_id` and the thresholds are not read.
* **Always empty.** For a consensus `options` is `[]` and `winnerOptionId` is `null`, also for an open consensus and also once
  `EVALUATED`: the room DTO never carries a rating, an option, a count, a time or another member. The compact result is loaded
  separately, and only for somebody the server lets read it (`getSystemicConsensusResult`).
  V1.9.42: for an anonymous consensus with fewer than five ratings in the current round that compact result carries no figures
  (`figuresWithheld`, empty `optionResults`); the operator step then lists the options in list order with the winner badge, the privacy sentence and the
  group-wide verdict in words, and no mean. See `consensus-ui.adoc`, "Minimum participation (V1.9.42)".
* **Own flags.** `ownEligible` is head-based: only an `ACTIVE` member (never a guest or friend, whatever a snapshot row says) with a
  snapshot row of the CURRENT round. `ownHasVoted` is read per round from `systemic_consensus_participation` (anonymous) or
  `systemic_consensus_ballot` (open), through the one place that already keeps the table separation (`SystemicConsensusOwnParticipation`);
  a rating of round 1 does not survive a `reopenRating`. At most three extra queries, however many consensuses are delivered.
* **One cap.** Elections, votes and consensuses share the cap of 20: every open ballot first, then the closed ones, then the
  decided ones newest first, so a decided consensus never displaces an open one.

=== Anonymous consensus is a secret ballot -- and the server already enforced it

The server-side stream lock was not new work. `castResistanceBallot` checks, fail-closed and before any write: active membership, status
`RATING`, and -- for an anonymous consensus only -- `SecretBallotStreamLock.requireStreamQuiescedForBallot`. `freezeOptions` and
`reopenRating` lock the rooms, mark the streams as pausing and quiesce them for an anonymous consensus; `hasOpenSecretBallotForMeeting`
(RATING) and `hasPendingOrOpenSecretBallot` (COLLECTION) cover it, so a room cannot be unbound from, or bound into, a Sitzung with
one. V1.9.32 adds the tests that pin this for the room (`SecretBallotStreamPauseTest` 15e--15h: a ballot while the stream is LIVE is
refused and writes nothing; an open consensus never pauses; COLLECTION locks nothing yet; a re-rating pauses again).

The client mirrors the rule in one pure function: `RoomBallotDto.isSecretBallotRunning()` is true for an election that is OPEN and
secret, and for a consensus that is `RATING` and anonymous -- never for one in `COLLECTION`, because the server pauses only when the
options are frozen. The banner and the 5-second stream poll of the screen use it; announcing a pause that is not happening would be wrong.

[source,kuml,name="conference-consensus-phases"]
----
stateDiagram(name = "Consensus phases in the room") {
    val start = initialState()
    val collection = state(name = "COLLECTION (room: OPEN, no lock)")
    val rating = state(name = "RATING (room: OPEN, anonymous: stream locked)")
    val closed = state(name = "CLOSED (room: CLOSED_AWAITING_TALLY)")
    val evaluated = state(name = "EVALUATED (room: DECIDED)")

    transition(source = start, target = collection) { trigger = "openSystemicConsensus" }
    transition(source = collection, target = rating) { trigger = "freezeOptions: pauses the streams if anonymous" }
    transition(source = rating, target = closed) { trigger = "closeRating: resumes the streams" }
    transition(source = closed, target = evaluated) { trigger = "evaluate" }
    transition(source = evaluated, target = rating) { trigger = "reopenRating: pauses again if anonymous" }
}
----

=== Client: card, compact booth, operator

* **Card** (`ConferenceConsensusCard.kt`): title, phase and anonymity badge ("anonym" or "offen – namentlich"), and -- in `RATING` only --
  the member's own standing. The single primary button "Bewerten" exists only for an eligible member who has not rated; a link "Wie
  funktioniert Konsensieren?" opens the overview in a new tab (`rel="noopener noreferrer"`). A guest, friend or federated guest sees the
  title and the badges only (`renderConsensusGuestRow`). Titles go through the untrusted-text helpers.
* **No single ballots (V1.9.44).** For an anonymous consensus no single ballot can be fetched at all (`listResistanceBallots` returns `[]` in every status, for every role); the conference path never reads the ballot or rating tables.
* **Booth.** The booth lives in the same booth host as the election booth and the bid view, so the close lock, the "no auto-open while it is
  open" rule and the unload prompt apply without new state. It is the real `ConsensusBooth`, given a `ConsensusBoothRoomHost`: the
  exit text ("Zurück zur Übersicht"), the stream lock (anonymous only), the busy signal and the compact grid. Without a host it renders exactly as
  before (a regression test pins it). The eleven fields of 0..10 stay in ONE row from a panel width of 290 px (`CONSENSUS_COMPACT_MIN_WIDTH_PX`);
  a narrower panel offers the booth as a link-button "In neuem Tab bewerten". The width is measured once, at the click, and a changed width
  never re-renders an open booth. The counter ("x von N bewertet") sits next to "Prüfen"; the scale sentence is the booth's existing one.
* **Lock.** While the stream of an anonymous consensus is still being paused the final "Endgültig abgeben" is disabled with a visible reason
  (`aria-describedby`), and freed without rebuilding the booth when the stream is quiet. The card shows the same reason beforehand.
* **Receipt.** The consensus booth reports its receipt through `consensusReceiptVisibilityHook`, not the election hook. The panel takes it
  through `ConferenceConsensusReceiptHookScope` (identity-checked restore) and sets the same RECEIPT lock, the same gate for the leave buttons
  and the unload prompt as for an election.
* **Operator** (`ConferenceConsensusOperator.kt`). The gate is the server's `SystemicConsensusParticipationDto.canManage`; room moderation
  alone gives none. Per phase: `COLLECTION` shows the option count and "Optionen festschreiben" (asks first; at least one option); `RATING`
  "Bewertung schließen" (asks first); `CLOSED` "Auswerten"; `EVALUATED` the ranking by mean resistance with the winner badge (no distribution,
  no named ratings) and "Erneut bewerten" (asks first) while `canReopen` allows it. The dialogs of the steps that start a rating round list the
  stream lines of an anonymous consensus, or say that the stream keeps running for an open one. Adding options, opening and aborting stay on the
  consensus page (new tab); the room never opens a consensus from a prepared motion.
* **Reads and writes.** The snapshot is read through the quiet `loadConsensusDetailQuietly`, at most every 30 seconds, after a phase change and
  when the panel opens, and never while it is hidden. Every write goes through the controller's one guarded function `runOperatorAction`
  (double-click guard, neutral conflict note, empty nudge, room reload); a tripwire pins it.
* **Emergency card.** An anonymous rating whose stream has not stopped after 60 seconds gives the moderation and a manager the same card as an
  election: "Stream stoppen" for the moderation and the link to the consensus page. A plain member only reads the lock text.
* **Badge and auto-open.** A consensus counts for the badge and opens the panel only in `RATING` and only for a member who can rate. The key
  under which it is remembered is dropped when it leaves `RATING`, so a re-rating is announced again.

=== Practice alignment (V1.9.39)

The compact booth lists the status quo option first and shows the option plaques (P, 1..n); a proposal's rationale sits behind a "Begründung"
switch (collapsed, so the 290 px panel stays narrow), and the legend follows the scale of the consensus. The operator's evaluated list shows
the plaques; it still carries no rationale. Details: `consensus-ui.adoc`, section "Practice alignment, part 1 (V1.9.39)".
