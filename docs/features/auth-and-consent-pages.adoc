= Sign-in and consent pages (V1.9.135)
:toc:

The five HTML pages of the sign-in and consent flows are rendered with kotlinx.html through one shell, `renderAuthPage` (`AuthPageHtml.kt`), and styled by the public site stylesheet (`/s/assets/style.css`).

== Pages and routes

[cols="2,3,1",options="header"]
|===
|Page |Route |`form-action`
|Guest consent |`GET /federation/oidc/authorize` (non-MCP scope) |none
|MCP consent |`GET /federation/oidc/authorize` (MCP scope) |none
|Home-server form |`GET /federation/oidc/rp/login` |none
|OIDC error page |error answers of `/federation/oidc/rp/login` and `/rp/callback` |`'self'`
|Keycloak error page |error answers of `/auth/keycloak/start` and `/callback` |`'self'`
|===

Routes, methods, status codes, cookies, rate limits and the checks of `state`, `nonce` and PKCE are unchanged.

== Shell without navigation

The header carries the brand only: no navigation, no language switcher, no call-to-action. Leaving a sign-in flow loses `state` and PKCE, so a navigation would only offer ways to break it. The brand link is the one way out. The doctype is written by hand because kotlinx.html emits none; without it the pages would run in quirks mode.

== Security headers

These headers are *newly introduced* in V1.9.135; none of the pages set any before.

* `Content-Security-Policy: default-src 'none'; style-src 'self'; img-src data: (plus 'self' with a logo); base-uri 'none'; frame-ancestors 'none'`, plus `form-action 'self'` where the table above says so.
* `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`, `Permissions-Policy` without geolocation, microphone and camera.
* `Referrer-Policy: same-origin`. `no-referrer` (as on the public pages) would make browsers send `Origin: null` on the form POST, which `isSameOriginRequest` answers with 403 on `POST /federation/oidc/rp/login`.
* No `form-action` on the consent pages and the home-server form: the 302 after the POST goes to a foreign origin, which Chrome checks against `form-action` and would block. For the home-server form that is the discovered `authorization_endpoint` of the (SSRF-checked) home server. The consent `redirect_uri` is validated against the client registration (`OidcRedirectUriMatcher`) before it is issued; the page builds no allowlist of its own.

== Escaping and no reflection

All text goes through kotlinx.html escaping; there is no `unsafe {}`, no script and no inline style. Error pages show enum constants only, so no typed address or token claim can appear in them. The consent pages show the host of the `redirect_uri` (never the whole URL, no port); the full URI exists only as a hidden field. The self-declared client name is filtered of control characters and capped at 80 characters.

== Language

German only. There is no language switcher and no new translation.

== Known limitations

* Not looked at in a real browser; `form-action` and `Referrer-Policy` are tested by header string only. The flow was not run against a real foreign home server.
* The guest consent page shows raw scope strings.
* The redirect line shows the host without a port ("127.0.0.1" for an MCP loopback client).

== Member-card verification and mailing-link pages (V1.9.136)

These pages render through the same shell (`renderAuthPage`) but are answered with `applyPublicPageHeaders`, not `applyAuthPageHeaders`: the URL carries a card code or a tracking token, so `Referrer-Policy` must be `no-referrer`, and there is no form that would need `same-origin`.

[cols="2,1,3"]
|===
| Page | Status | Notes

| Member card, valid | 200 | Name in a green success callout, three facts as a definition list ("Mitgliedsnummer", "Status", "Mitglied seit"; the colon after the labels no longer exists). No actions.
| Member card, invalid | 200 | One neutral page for unknown, revoked, malformed and former-member codes; byte-identical, no red alarm because the result concerns a person.
| Member card, too many requests | 429 | `Retry-After: 60`.
| Member card, error | 500 | Fixed text.
| Mailing link not found | 404 | One page for every failure of the click route; no `Location`.
| Mailing, too many requests | 429 | `Retry-After: 60`.
|===

Headers: member card pages add `X-Robots-Tag: noindex, nofollow` and `Cache-Control: no-store`; mailing pages carry `X-Robots-Tag: noindex` and `no-store`. With a logo configured the CSP allows `img-src 'self'`.

There is no token-based unsubscribe page, so no link scanner can trigger an unsubscribe. Required mailing lists explain this without a link; dynamic lists point to `${publicBaseUrl}/app` in text. Scanner pre-fetches of `/m/c/` still count as clicks (unchanged); `HEAD` requests do not.
