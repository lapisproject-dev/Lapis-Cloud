= Mail language of the instance
:toc:

Since V1.9.332 an ADMIN can set the language in which the instance sends *single-language* mails
(Organisation page, section "Allgemein", "E-Mails"). The setting is `organization_settings.mail_language`
(migration V176, default `de`). It is changed only through `IOrganizationSettingsService.updateMailLanguage`
(ADMIN, audited on change); the generic settings update never touches it.

== Supported languages

`de`, `en`, `es`, `fr`, `it`, `nl`, `pl`, `ru` (the codes of `MembershipDecisionTexts.SUPPORTED`). The RPC
accepts exactly these codes: no trimming, no case folding. A value outside the list in the column reads as `de`.

== Which language a mail uses

`MailLanguage.resolve(recipient, instance)`:

. the recipient's own language, if it is a supported code;
. otherwise the instance language;
. otherwise `de`.

The instance language is read when the mail is sent, not when the event happens, so a change applies without a
restart. A setting that cannot be read never blocks a mail: it falls back to `de`.

== Scope today

Since V1.9.334 every system mail below is written in ONE language, the instance language (no member has a
language of their own, so the recipient language is always empty for them):

[cols="2,2,3",options="header"]
|===
| Mail | Recipient | Note
| Password reset | member | link + code, TTL with plural form
| Auditor code (`partgReviewerCode`) | external auditor without account | fixed wording, no link
| Friend e-mail verification | friend/guest address |
| Webhook endpoint deactivated | board/administrators | unknown host is written in the mail language
| FinTS re-authentication | board/administrators | raw timestamp
| Password reset by an administrator | member | raw timestamp, no password
| Keycloak link changed (linked/unlinked) | member | no Keycloak subject, no actor
| Keycloak member provisioned / e-mail synced | administrators / old address |
| Article review (published/rejected/unpublished) | author | title only sanitised in the subject
| E-mail change (confirm, warning, self info, applied info) | new/old address | links and tokens unchanged
| Encounter entry notice | office holders | person counts number-neutral outside de/en
| Carpool notice (8 kinds) | driver/rider | no names, no content
| Peer protection (request, approval needed, executed, reset triggered, protected data, new administrator) | target/administrators | the operator console writes the actor name in the mail language
| Tender payout receipt / failure notice (V1.9.330-332) | winner / board | footer localised since V1.9.334
| Event mails (V1.9.335): waitlist spot, registration (confirmed / waitlisted / payment pending), notice to an account holder, duplicate notice, ticket after payment, ticket reissue, cancellation, registration-message notice | registrant (member or guest) / event creator | no footer (as before); no date, time or attachment in any of them; the cancellation reason stays board free text
|===

Not single-language in the instance language, on purpose:

* the membership decision mails (approved/rejected): the language chosen in the board dialog (`mailLanguage`) plus a de/en second block
  (V1.9.118). Since V1.9.335 an empty or unknown code falls back to the instance language instead of `de` (only API/MCP callers can send
  one; the dialog always sends a code). Since V1.9.336 the setting also preselects the language in the decision dialogs (German if it cannot be loaded or is unknown); the board may change it per decision. A change made while the page is open applies after a reload;
* newsletters and mailings: they carry their own language.

Event mails: members have no stored language and the language of a guest is not reliably known (the public page learns the visitor
language only from `?lang=`, which is absent for `de` and lost in the embed mode, and the registration stores none), so all of them use the
instance language. Wording lives in `EventMailTexts.kt`, layout in `EventMailTemplates.kt`.

The footer ("Questions? ...") and the "unknown" time are localised in all of them.

== Translations

The German texts are the original wording. The translations into the other seven languages were written by the
model and are *not reviewed by native speakers*. Each wording is one `MailText` with eight languages side by side; a
completeness test checks that all eight exist and carry the same placeholders.

== Known limits

* Amounts keep the decimal comma and timestamps the `yyyy-MM-dd HH:mm UTC` form in every language; the FinTS and administrator-reset mails keep a raw `yyyy-MM-ddTHH:mm` timestamp.
* Plural forms: hours and minutes follow one/few/many for `pl` and `ru`; the person counts of the encounter notice are phrased number-neutrally in es/fr/it/nl/pl/ru.
* The language list exists twice (server and client); a test keeps both in step.
* Backup restore: a bundle without the column gets `de`; a value outside the list is refused.
