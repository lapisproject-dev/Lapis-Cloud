= Branding (logo in the navbar)
:toc:

Operators can show their own logo instead of the default Lapis Cloud mark. Without a logo the mark is shown next to the title, whatever the title is (since V1.9.214). The logo is served at
`/api/branding/logo`; the architecture of the public chrome is described in
`docs/architecture/public-chrome.adoc`.
Colours, corner radius and fonts are a separate feature: see link:theming.adoc[Themes from files].

== Logo recommendations

* Use a transparent PNG or an SVG. Any aspect ratio works.
* The logo is shown *32 px tall* in the navbar (the height scales with the text zoom), at most
  *240 px wide* (160 px on phones). In the login lockup it is *40 px tall*, at most 240 px wide.
  A wider logo is scaled down to fit, never cropped.
* The public pages (articles, events, transparency, sign-in and so on) use the same 32 px height and the same width
  limits (240 px, 160 px under 768 px; 180/120 px before V1.9.284).
* For sharp rendering use an SVG, or a PNG that is at least 96 px tall.
* Do not add your own padding inside the image: the spacing to the title comes from the interface.
* For a title logo supply a *tight crop*: no tagline or subtitle, no padding, about *12:1* and at least *1200 px wide*, in a light and a dark
  variant. An SVG needs a `viewBox`, otherwise it renders as a wide area with margins. An image with a subtitle or padding looks small: the
  box is 32 px high and the width is capped, so a 12.4:1 title is about 19 px tall at 240 px (about 13 px at 160 px on phones).

== Logo variants (V1.9.265)

Besides the single legacy logo (`LAPIS_BRAND_LOGO_PATH`) an operator can configure four files: a *signet* (compact, navbar) and a *wordmark* (spells the
name, sign-in lockup and public page header), each for a *light* and a *dark* page.

[cols="2,3",options="header"]
|===
| Variable | Route
| `LAPIS_BRAND_SIGNET_LIGHT_PATH` | `/api/branding/logo/signet-light`
| `LAPIS_BRAND_SIGNET_DARK_PATH` | `/api/branding/logo/signet-dark`
| `LAPIS_BRAND_WORDMARK_LIGHT_PATH` | `/api/branding/logo/wordmark-light`
| `LAPIS_BRAND_WORDMARK_DARK_PATH` | `/api/branding/logo/wordmark-dark`
|===

Each file is an absolute in-container path (`deploy/example/branding` is mounted at `/app/branding`), `.svg`, `.png` or `.webp`, at most 512 KiB, no `..`
segment. A file that is missing, unreadable or too large disables that one variant with a `WARN` that names the variable (never the path).

=== Which kind is used where (V1.9.284)

The header (the public pages and the signed-in navbar) shows the *wordmark*: the same resolved chain, so both show the same logo. The signet is
used only as a fallback when no wordmark is configured. Where the wordmark is shown it spells the name, so the text label next to it is left out.
The sign-in lockup also uses the wordmark. Supply *both modes of the wordmark*: with only a light wordmark and a dark signet the dark navbar shows
the light wordmark, i.e. dark artwork on a dark bar. An instance with only a signet is unchanged and keeps the title next to it.

=== Fallback chain

A slot (mode x kind) takes the first available source: same kind in its own mode, same kind in the other mode, the other kind in the own mode, the other
kind in the other mode, the legacy logo, the built-in Lapis Cloud mark. So one file is enough; an instance without any new variable is unchanged.
Limit: with only the other kind configured, a light file can end up on a dark page.

=== Behaviour

* "Dark" means artwork made for a dark background (light strokes). In the signed-in navbar and in the public header the variant follows the lightness of the `nav` colour of the current mode, not the page mode: a dark `nav` shows the dark variant, a light `nav` the light one (WCAG equal-contrast rule, ties count as dark). The choice is written into `/theme.css`; without `/theme.css` the public header shows the light image. The sign-in lockup (on the page background) still follows `data-theme`. Exactly one image is shown at a time.
* A wordmark that is used for both modes of a kind carries the name: the text label next to it is omitted and the image `alt` is the title.
* The default theme's top bar (`nav` token) is dark in both modes, so an instance with the default theme and logo variants always shows the *dark* variant in the navbar and the public header. Check that your `*_DARK_PATH` files are real negatives (light artwork for a dark ground).
* Not yet covered: the built-in Lapis Cloud mark alone in the navbar (no logo configured) still follows `data-theme`; moving it to the `nav` rule is a separate decision.
* `og:image` and the JSON-LD image use the first raster logo (wordmark-light, signet-light, wordmark-dark, signet-dark, legacy); an SVG is never used.
* The video-overlay instance logo is the file `GET /api/branding/logo` serves (legacy logo, else the light signet of the chain); an SVG is not offered.
* The sign-in and public pages allow `img-src 'self'` whenever any logo is served.
